## 2. 依赖服务

### 2.1 服务器部署（当前使用）

服务器 `172.16.112.183`（Ubuntu 24.04，Docker 29.4.3，Compose v5.1.3）家目录下的项目目录：

~~~text
~/orange-forge/
├── .env           仅存在于服务器，权限 600，不进入代码仓库
└── compose.yaml   MySQL 8.4.11 与 Redis 8.10.1-alpine，固定镜像标签与命名卷
~~~

端口说明：该服务器 3306 已被另一项目的 MySQL 占用，因此本项目使用独立端口，避免影响他人服务。

| 服务 | 宿主端口 | 容器内端口 | 命名卷 |
| --- | --- | --- | --- |
| MySQL | 3307 | 3306 | orange-forge-mysql-data |
| Redis | 6380 | 6379 | orange-forge-redis-data |

日常操作（在服务器上执行，工作目录 `~/orange-forge`）：

~~~bash
docker compose --env-file .env -f compose.yaml ps
docker compose --env-file .env -f compose.yaml stop     # 保留命名卷
docker compose --env-file .env -f compose.yaml up -d --wait
~~~

首次部署或重建时先校验配置再启动：

~~~bash
docker compose --env-file .env -f compose.yaml config --quiet
docker compose --env-file .env -f compose.yaml up -d --wait --wait-timeout 300
~~~

MySQL 初始化变量只在空数据目录时创建账号与数据库。已有数据卷后修改 `.env` 不会自动修改数据库内密码，需显式维护（例如 `ALTER USER`），不能通过删除数据卷规避问题。

### 2.2 本机 Compose（备用，当前未安装 Docker）

## 3. 后端

工作目录：`backend`。

~~~powershell
cd backend

# 构建并运行全部检查
.\mvnw.cmd -B clean test

# 打包（产出可执行 jar：forge-application/target/forge-application-1.0.0.jar）
.\mvnw.cmd -B package

# 仅跑架构规则
.\mvnw.cmd -B -pl forge-application -am test "-Dtest=Module*" "-Dsurefire.failIfNoSpecifiedTests=false"
~~~

启动应用前设置连接参数（未设置时使用 `application.yaml` 中的本机默认值）：

~~~powershell
$env:FORGE_MASTER_URL = 'jdbc:mysql://172.16.112.183:3307/orange_forge?useUnicode=true&characterEncoding=utf8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
$env:FORGE_MASTER_USERNAME = 'forge'
$env:FORGE_MASTER_PASSWORD = '<服务器的 MYSQL_PASSWORD>'
$env:FORGE_REDIS_HOST = '172.16.112.183'
$env:FORGE_REDIS_PORT = '6380'
$env:FORGE_REDIS_PASSWORD = '<服务器的 REDIS_PASSWORD>'

java -jar forge-application\target\forge-application-1.0.0.jar
~~~

默认端口 8080，可用 `FORGE_SERVER_PORT` 覆盖。不依赖外部 MySQL 与 Redis 的本机演示启动（内存库，含 H2 运行时依赖）：

~~~powershell
.\mvnw.cmd -B -pl forge-application -am -DskipTests install
java -jar forge-application\target\forge-application-1.0.0.jar --spring.profiles.active=standalone --server.port=18080
~~~

`standalone` profile 定义在 `application-standalone.yaml`，只用于本机验证接口与文档，不代表生产部署方案。

启动后可访问：

~~~powershell
# 示例接口，验证统一响应与追踪编号
Invoke-WebRequest 'http://127.0.0.1:8080/api/admin/v1/example/hello' -UseBasicParsing

# 公共能力验证接口（参数校验、字符串 ID、枚举代码）
Invoke-WebRequest 'http://127.0.0.1:8080/api/admin/v1/example/validation/123?pageSize=10&status=active' -UseBasicParsing

# 失败路径：非法枚举代码应返回 HTTP 200 + body.code=400
Invoke-WebRequest 'http://127.0.0.1:8080/api/admin/v1/example/validation/123?status=unknown' -UseBasicParsing

# API 文档分组与界面
Invoke-WebRequest 'http://127.0.0.1:8080/v3/api-docs/admin' -UseBasicParsing
Invoke-WebRequest 'http://127.0.0.1:8080/v3/api-docs/app' -UseBasicParsing
Invoke-WebRequest 'http://127.0.0.1:8080/swagger-ui/index.html' -UseBasicParsing
~~~

数据库迁移由 `forge-framework` 的 `FlywayConfig` 显式针对主库执行，只加载 `classpath:db/migration`。
M1 阶段没有迁移脚本，因此空库初始化只创建 `flyway_schema_history`；重复启动验证通过并且不重复执行。
脚本目录说明见 `backend/forge-application/src/main/resources/db/migration/迁移说明.md`。

真实中间件探针（默认构建会跳过，用于确认核心组合）：

~~~powershell
.\mvnw.cmd -B -pl forge-application -am test "-Dtest=DependencyProbeTest" "-Dsurefire.failIfNoSpecifiedTests=false"
~~~

需要已经设置上表中的连接参数环境变量；`FORGE_MASTER_URL` 存在时该用例必须真实通过。

### 依赖服务验收命令

以下命令用于复核依赖服务本身（在服务器上执行），2026-09-14 初始验收已实际执行并通过。`<密码>` 取自服务器 `~/orange-forge/.env`。

~~~bash
# MySQL：应用账号可查询，字符集与时间语义正确
docker exec orange-forge-mysql mysql -uforge -p'<MYSQL_PASSWORD>' -N \
  -e "select current_user(), @@character_set_server, @@time_zone;"

# MySQL：迁移历史（M1 无业务迁移时为 0 行）
docker exec orange-forge-mysql mysql -uforge -p'<MYSQL_PASSWORD>' orange_forge \
  -e "select installed_rank, version, description, success from flyway_schema_history;"

# Redis：未认证必须被拒绝
docker exec orange-forge-redis redis-cli ping
# 预期输出：NOAUTH Authentication required.

# Redis：认证后可读写，确认 AOF 已开启
docker exec -e REDISCLI_AUTH='<REDIS_PASSWORD>' orange-forge-redis redis-cli set forge:probe ok
docker exec -e REDISCLI_AUTH='<REDIS_PASSWORD>' orange-forge-redis redis-cli config get appendonly

# 重启后数据仍在（不得删除命名卷）
docker compose --env-file .env -f compose.yaml restart
docker compose --env-file .env -f compose.yaml ps
~~~

## 4. 前端

工作目录：`frontend`。

~~~powershell
cd frontend

pnpm install            # 首次或依赖变更后
pnpm run type-check     # 三个工作区包的严格类型检查
pnpm run lint           # ESLint 平坦配置
pnpm run test           # Vitest（公共请求包协议分流用例）
pnpm run build          # 两个应用与公共包的构建

pnpm run dev:admin      # 管理端，http://localhost:5173
pnpm run dev:portal     # 用户端，http://localhost:5174
~~~

开发服务器默认把 `/api` 代理到 `http://127.0.0.1:8080`。公共默认值位于各应用 `.env`，用 `.env.local` 中的 `VITE_API_PROXY_PREFIX`、`VITE_API_PROXY_TARGET` 覆盖；端口冲突会明确失败，用 `VITE_DEV_PORT` 调整后重启，不要停止其他项目进程。Vite 配置已通过 `loadEnv` 读取这些文件。

接口基础地址来自各应用自己的 `.env` 与 `.env.local`（模板为 `.env.example`），不写死域名。公共请求工厂在 HTTP 200 下仍检查 `body.code`：

- `code=0` 返回业务数据，`data` 为 `null` 表示该用例没有业务数据。
- `code=401/403` 触发对应钩子后再抛出，其余非零 code 触发统一错误钩子。
- 结构不符合协议按协议异常处理，连接、超时与代理错误按传输异常处理。

令牌读写、路由与账号状态属于各应用自己，不进入公共包；认证页面与接口在 M3 实现。

### 接口类型生成（M2）

公共包按后端 OpenAPI 分组生成接口类型，生成结果纳入类型检查：

~~~powershell
# 1. 先启动后端（standalone 或连接真实依赖均可），确认 /v3/api-docs/admin 可访问
# 2. 在 frontend 目录执行
cd frontend
pnpm install                                    # 首次或依赖变更后，安装锁定的生成工具
cd packages/api-client
$env:FORGE_OPENAPI_BASE_URL = 'http://127.0.0.1:18080'   # 缺省为 http://127.0.0.1:8080
pnpm run generate:api-types
~~~

生成结果写入 `src/generated/admin.ts`、`src/generated/app.ts`，中间规范快照 `*.openapi.json` 不进入版本管理。
生成工具版本在 `packages/api-client/package.json` 中锁定为 `openapi-typescript@7.10.1`，生成文件不手工修改。

## 5. 配置在哪里改

项目级常量与可调参数集中在 `backend/forge-application/src/main/resources/application.yaml`，
按用途分组，改完重启即可生效，不需要改代码。规则见[配置管理规范](conventions/配置管理规范.md)。

| 配置项 | 作用 | 默认值 |
| --- | --- | --- |
| `server.port` | 后端端口 | 8080 |
| `spring.datasource.dynamic.primary` / `forge.datasource.primary-name` | 主库名称，Flyway 等只作用于主库的能力读取它 | master |
| `spring.datasource.dynamic.datasource.master.*` | 主库连接、驱动与 Hikari 连接池 | 见文件注释 |
| `forge.secondary-datasource.*` | 可选第二数据源：`enabled`、名称、连接与连接池；关闭时不注册，使用该名称会报错 | 关闭 |
| `spring.flyway.*` | 迁移开关、目录、基线与校验 | 启用，`classpath:db/migration` |
| `spring.data.redis.*` | Redis 地址、库号、超时与连接池 | 本机 6379 |
| `forge.redis.key-prefix` / `default-ttl-seconds` | Redis 键前缀（项目:环境）与默认缓存存活秒数 | forge:local / 600 |
| `forge.mybatis-plus.db-type` | 分页方言对应的数据库类型 | MYSQL |
| `forge.page.default-page-num` / `default-page-size` / `max-size` | 分页默认页码、默认条数与每页上限 | 1 / 20 / 100 |
| `forge.web.display-zone` / `trace-enabled` / `trace-header-name` | 展示时区、追踪开关、追踪响应头名称 | UTC / true / X-Trace-Id |
| `spring.servlet.multipart.max-file-size` / `max-request-size` | 上传硬上限 | 50MB / 60MB |
| `springdoc.api-docs.enabled` / `swagger-ui.enabled` | API 文档与界面，生产应关闭 | true（local 开启） |
| `logging.level.*` | 各包日志级别 | 见文件注释 |

启动时可在命令行临时覆盖，用于排查而不改文件：

~~~powershell
java -jar forge-application\target\forge-application-1.0.0.jar `
  --server.port=18080 `
  --forge.page.max-size=250 `
  --forge.web.trace-header-name=X-Forge-Trace
~~~

越界配置不会带病启动：例如 `--forge.page.max-size=5000` 会直接启动失败并指出
`Property: forge.page.maxPageSize`。修改 `application.yaml` 后请先 `.\mvnw.cmd -B clean install`，
不要只跑增量构建：只改配置类而未重编译时，旧 class 会继续生效，容易得出错误结论。

## 7. GitHub 仓库与提交身份

远程仓库为 [OrangeNode/forge](https://github.com/OrangeNode/forge)，本地分支为 `main`，`origin` 使用 `git@github.com:OrangeNode/forge.git`。2026-09-29 已验证本机 SSH 认证账号为 `OrangeNode`。

本项目使用仓库级提交身份，避免继承机器上其他项目使用的真实姓名或工作邮箱。在新克隆的项目根目录执行以下配置；这些本地设置不会随克隆复制：

~~~powershell
git config --local user.name OrangeNode
git config --local user.email 80626832+OrangeNode@users.noreply.github.com
git config --local user.useConfigOnly true
~~~

提交前用 `git var GIT_AUTHOR_IDENT` 和 `git var GIT_COMMITTER_IDENT` 核对实际身份；上传前用 `git log --all --format='%h %an <%ae> | %cn <%ce>'` 检查历史作者与提交者。修改配置不会自动修正已有提交，首次发布前已重写唯一的本地旧提交身份，源码内容保留。

首次上传命令为 `git push -u origin main`，后续使用 `git push`。只上传目标分支，不使用镜像推送；本地恢复记录不作为发布历史上传。提交名称与邮箱控制公开提交署名，SSH 密钥决定 GitHub 认证账号，二者需分别核对。
