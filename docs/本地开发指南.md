## 2. 依赖服务

### 2.1 服务器部署（当前使用）

服务器 `172.16.112.183`（Ubuntu 24.04，Docker 29.4.3，Compose v5.1.3）家目录下的项目目录：

~~~text
~/orange-forge/
├── .env           仅存在于服务器，权限 600，不进入代码仓库
└── compose.yaml   MySQL 8.4.11 与 Redis 8.10.1-alpine，固定镜像标签与命名卷
~~~

端口说明：该服务器 3306 已被另一项目的 MySQL 占用，因此本项目使用独立端口，避免影响他人服务。

| 服务 | 宿主端口 | 容器内端口 | 命名卷 |
| --- | --- | --- | --- |
| MySQL | 3307 | 3306 | orange-forge-mysql-data |
| Redis | 6380 | 6379 | orange-forge-redis-data |

日常操作（在服务器上执行，工作目录 `~/orange-forge`）：

~~~bash
docker compose --env-file .env -f compose.yaml ps
docker compose --env-file .env -f compose.yaml stop     # 保留命名卷
docker compose --env-file .env -f compose.yaml up -d --wait
~~~

首次部署或重建时先校验配置再启动：

~~~bash
docker compose --env-file .env -f compose.yaml config --quiet
docker compose --env-file .env -f compose.yaml up -d --wait --wait-timeout 300
~~~

MySQL 初始化变量只在空数据目录时创建账号与数据库。已有数据卷后修改 `.env` 不会自动修改数据库内密码，需显式维护（例如 `ALTER USER`），不能通过删除数据卷规避问题。

## 3. 后端

工作目录：`backend`。

~~~powershell
cd backend

# 构建并运行全部检查
.\mvnw.cmd -B clean test

# 打包（产出可执行 jar：forge-application/target/forge-application-1.0.0.jar）
.\mvnw.cmd -B package

# 仅跑架构规则
.\mvnw.cmd -B -pl forge-application -am test "-Dtest=Module*" "-Dsurefire.failIfNoSpecifiedTests=false"
~~~

启动应用前设置连接参数（未设置时使用 `application.yaml` 中的本机默认值）：

~~~powershell
$env:FORGE_MASTER_URL = 'jdbc:mysql://172.16.112.183:3307/orange_forge?useUnicode=true&characterEncoding=utf8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
$env:FORGE_MASTER_USERNAME = 'forge'
$env:FORGE_MASTER_PASSWORD = '<服务器的 MYSQL_PASSWORD>'
$env:FORGE_REDIS_HOST = '172.16.112.183'
$env:FORGE_REDIS_PORT = '6380'
$env:FORGE_REDIS_PASSWORD = '<服务器的 REDIS_PASSWORD>'

java -jar forge-application\target\forge-application-1.0.0.jar
~~~

默认端口 8080，可用 `FORGE_SERVER_PORT` 覆盖。不依赖外部 MySQL 与 Redis 的本机演示启动（内存库，含 H2 运行时依赖）：

~~~powershell
.\mvnw.cmd -B -pl forge-application -am -DskipTests install
java -jar forge-application\target\forge-application-1.0.0.jar --spring.profiles.active=standalone --server.port=18080
~~~

`standalone` profile 定义在 `application-standalone.yaml`，只用于本机验证接口与文档，不代表生产部署方案；内存库没有系统表，因此该 profile 关闭了初始管理员引导。

首次在空库上启动（M3 起）需要提供初始管理员凭据，否则启动会明确失败：

~~~powershell
$env:FORGE_INIT_ADMIN_USERNAME = 'forge-admin'
$env:FORGE_INIT_ADMIN_PASSWORD = '<自行设定的初始口令，8—64 个字符>'
$env:FORGE_INIT_ADMIN_DISPLAY_NAME = '初始管理员'
java -jar forge-application\target\forge-application-1.0.0.jar
~~~

引导只在 `sys_admin` 为空时创建账号并授予超级管理员角色，已有管理员时不做任何修改；不需要引导时设置 `FORGE_INIT_ADMIN_ENABLED=false`。

启动后可访问（M3 起受保护接口需要 Bearer 令牌，只有登录接口与文档路径匿名可达）：

~~~powershell
# 登录并取得令牌（用户名不区分大小写）
$login = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/login' `
  -ContentType 'application/json' -Body '{"username":"forge-admin","password":"<初始口令>"}'
$token = $login.data.accessToken

# 当前身份与权限、当前菜单
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/me' -Headers @{Authorization="Bearer $token"}
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/menus' -Headers @{Authorization="Bearer $token"}

# 失败路径：密码错误返回 HTTP 200 + body.code=401；未带令牌访问受保护路径同样是 401
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/login' `
  -ContentType 'application/json' -Body '{"username":"forge-admin","password":"wrong"}'
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/me'

# 退出后原令牌立即失效
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/logout' -Headers @{Authorization="Bearer $token"}

# 示例接口与文档（示例接口不再是匿名路径，需带令牌；文档路径默认放行，文档只在开发 profile 开启）
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/example/hello' -Headers @{Authorization="Bearer $token"}
Invoke-WebRequest 'http://127.0.0.1:8080/v3/api-docs/admin' -UseBasicParsing
Invoke-WebRequest 'http://127.0.0.1:8080/swagger-ui/index.html' -UseBasicParsing
~~~

数据库迁移由 `forge-framework` 的 `FlywayConfig` 显式针对主库执行，只加载 `classpath:db/migration`，并遵循 `spring.flyway.enabled`。
M3 新增 `db/migration/system/V20260930120000__init_system_tables.sql`：在真实 MySQL 8.4 上执行成功，重复启动显示 `Schema is up to date. No migration necessary.`。
脚本目录说明见 `backend/forge-application/src/main/resources/db/migration/迁移说明.md`。

真实中间件探针（默认构建会跳过，用于确认核心组合）：

## 4. 前端

工作目录：`frontend`。

~~~powershell
cd frontend

pnpm install            # 首次或依赖变更后
pnpm run type-check     # 两个工作区包的严格类型检查
pnpm run lint           # ESLint 平坦配置
pnpm run test           # Vitest（公共请求包协议分流用例）
pnpm run build          # 后台管理前端与公共包的构建

pnpm run dev:admin      # 后台管理前端，http://localhost:5173
~~~

开发服务器默认把 `/api` 代理到 `http://127.0.0.1:8080`。公共默认值位于 `admin/.env`，用 `.env.local` 中的 `VITE_API_PROXY_PREFIX`、`VITE_API_PROXY_TARGET` 覆盖；端口冲突会明确失败，用 `VITE_DEV_PORT` 调整后重启，不要停止其他项目进程。Vite 配置已通过 `loadEnv` 读取这些文件。

接口基础地址来自后台管理前端的 `.env` 与 `.env.local`（模板为 `.env.example`），不写死域名。公共请求工厂在 HTTP 200 下仍检查 `body.code`：

- `code=0` 返回业务数据，`data` 为 `null` 表示该用例没有业务数据。
- `code=401/403` 触发对应钩子后再抛出，其余非零 code 触发统一错误钩子。
- 结构不符合协议按协议异常处理，连接、超时与代理错误按传输异常处理。

令牌读写、路由与账号状态属于前端应用自己，不进入公共包；公共请求工厂通过 `tokenProvider` 接收应用的令牌读取函数。M3 已实现登录页、路由守卫与权限菜单（只搭结构，视觉样式待设计确定后调整）：

- 登录后令牌写入 `sessionStorage`（键名 `orange-forge:admin:token`），受保护接口自动携带 `Authorization: Bearer <token>`。
- 受保护请求返回 `body.code=401` 时清理会话并跳转登录页；登录接口的 401 只提示凭据错误，不跳转。
- 侧边栏菜单来自 `/api/admin/v1/auth/menus`，并经过 `src/router/menu-routes.ts` 的白名单映射，未登记的标识不渲染。

受限执行环境的注意事项：

- 受限环境下 Maven 不能写入 `C:\Users\<用户>\.m2`，使用 `-s ..\.mvn-local-settings.xml` 把本地仓库指向仓库内 `.m2repo`；该文件与目录都不进入版本管理。
- 沙箱禁止 JVM 自附加与管道方式派生子进程时，Mockito 用例会报 `MockitoInitializationException`，vitest/vite 会报 `spawn EPERM`。这些是执行环境限制而非代码缺陷，需在放宽权限的终端中运行。

## 7. GitHub 仓库与提交身份

远程仓库为 [OrangeNode/forge](https://github.com/OrangeNode/forge)，本地分支为 `main`，`origin` 使用 `git@github.com:OrangeNode/forge.git`。2026-09-29 已验证本机 SSH 认证账号为 `OrangeNode`。

本项目使用仓库级提交身份，避免继承机器上其他项目使用的真实姓名或工作邮箱。在新克隆的项目根目录执行以下配置；这些本地设置不会随克隆复制：

~~~powershell
git config --local user.name OrangeNode
git config --local user.email 80626832+OrangeNode@users.noreply.github.com
git config --local user.useConfigOnly true
~~~

提交前用 `git var GIT_AUTHOR_IDENT` 和 `git var GIT_COMMITTER_IDENT` 核对实际身份；上传前用 `git log --all --format='%h %an <%ae> | %cn <%ce>'` 检查历史作者与提交者。修改配置不会自动修正已有提交，首次发布前已重写唯一的本地旧提交身份，源码内容保留。

首次上传命令为 `git push -u origin main`，后续使用 `git push`。只上传目标分支，不使用镜像推送；本地恢复记录不作为发布历史上传。提交名称与邮箱控制公开提交署名，SSH 密钥决定 GitHub 认证账号，二者需分别核对。
