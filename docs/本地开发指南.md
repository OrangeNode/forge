## 2. 依赖服务

### 2.1 本机 Docker Desktop（当前使用）

MySQL 8.4.11 与 Redis 8.10.1-alpine 由 `docker/compose.yaml` 定义，在本机 Docker Desktop（WSL2 后端）中运行，端口只绑定 `127.0.0.1`。数据保存在 Docker 命名卷 `orange-forge_mysql-data`、`orange-forge_redis-data`，不写入项目目录。

| 服务 | 本机端口 | 命名卷 |
| --- | --- | --- |
| MySQL | 3306 | orange-forge_mysql-data |
| Redis | 6379 | orange-forge_redis-data |

凭据在项目根目录 `.env.local`（模板 `.env.example`，不进入版本库）：`MYSQL_PASSWORD`、`REDIS_PASSWORD` 需与后端 `FORGE_MASTER_PASSWORD`、`FORGE_REDIS_PASSWORD` 一致，`application.yaml` 的本机默认值已与之对应。端口冲突时改 `.env.local` 中的 `MYSQL_PORT`、`REDIS_PORT`，并同步后端连接变量。

拉取镜像需要代理时，在 Docker Desktop「Settings → Resources → Proxies」中设置（默认跟随 Windows 系统代理）。

在项目根目录（PowerShell）执行：

~~~powershell
docker compose --env-file .env.local -f docker/compose.yaml up -d --wait
docker compose --env-file .env.local -f docker/compose.yaml ps
docker compose --env-file .env.local -f docker/compose.yaml stop    # 保留命名卷
~~~

MySQL 初始化变量只在空数据卷时创建账号与数据库；已有数据卷后修改 `.env.local` 不会自动修改数据库内密码，需显式 `ALTER USER`，不能通过删除数据卷规避问题。空库首次启动后端时由 Flyway 建表，并按第 3 节引导初始管理员。

### 2.2 MinIO（S3 兼容存储，验收用）

`docker/compose.yaml` 内有一段被注释的 `minio` 服务与 `minio-data` 卷，只用于文件存储的 S3 适配验收。启用方式：取消注释 → 在 `.env.local` 中设置 `MINIO_ROOT_USER` 与 `MINIO_ROOT_PASSWORD` → `docker compose up -d minio`。控制台为 `http://127.0.0.1:9001`，S3 端点为 `http://127.0.0.1:9000`。

2026-09-29 的真实验收在测试服务器上以等价命令完成（服务需从本机访问，因此端口绑定到服务器网卡而不是回环地址）：

~~~bash
docker volume create forge-minio-data
docker run -d --name orange-forge-minio --restart unless-stopped \
  -p 9000:9000 -p 9001:9001 \
  -e MINIO_ROOT_USER=forge-minio -e MINIO_ROOT_PASSWORD='<自行设定>' \
  -v forge-minio-data:/data minio/minio:latest server /data --console-address ':9001'
# 镜像自带 mc：创建验收用的 bucket
docker exec orange-forge-minio mc alias set local http://127.0.0.1:9000 forge-minio '<自行设定>'
docker exec orange-forge-minio mc mb --ignore-existing local/forge-files
~~~

后端侧需要提供凭据加密主密钥并指定本地目录，然后在管理端「存储配置」里新增 s3 方案（endpoint、region、bucket、path-style 打开、accessKey/secretKey）：

~~~powershell
$env:FORGE_FILE_ENCRYPTION_KEY = '<Base64 编码的 32 字节密钥>'
$env:FORGE_FILE_LOCAL_ROOT = "$env:TEMP\forge-files"
java -jar forge-application\target\forge-application-1.0.0.jar
~~~

自动化验收（默认跳过，设置环境变量后执行）：

~~~powershell
$env:FORGE_S3_TEST_ENDPOINT = 'http://<minio 主机>:9000'
$env:FORGE_S3_TEST_BUCKET = 'forge-files'
$env:FORGE_S3_TEST_ACCESS_KEY = '<accessKey>'
$env:FORGE_S3_TEST_SECRET_KEY = '<secretKey>'
.\mvnw.cmd -B test "-Dtest=MinioS3IntegrationTest" "-Dsurefire.failIfNoSpecifiedTests=true"
~~~

## 3. 后端

工作目录：`backend`。

~~~powershell
cd backend

# 构建并运行全部检查
.\mvnw.cmd -B clean test

# 打包（产出可执行 jar：forge-application/target/forge-application-1.0.0.jar）
.\mvnw.cmd -B package

# 仅跑架构规则
.\mvnw.cmd -B -pl forge-application -am test "-Dtest=Module*" "-Dsurefire.failIfNoSpecifiedTests=false"
~~~

`application.yaml` 的本机默认值直接指向本机 Docker 中的依赖（`127.0.0.1:3306`、`127.0.0.1:6379`），按第 2.1 节启动依赖后无需额外变量；端口或密码与默认值不同时再覆盖：

~~~powershell
$env:FORGE_MASTER_URL = 'jdbc:mysql://127.0.0.1:3306/orange_forge?useUnicode=true&characterEncoding=utf8&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC'
$env:FORGE_MASTER_PASSWORD = '<.env.local 中的 MYSQL_PASSWORD>'
$env:FORGE_REDIS_PORT = '6379'
$env:FORGE_REDIS_PASSWORD = '<.env.local 中的 REDIS_PASSWORD>'

java -jar forge-application\target\forge-application-1.0.0.jar
~~~

默认端口 8080，可用 `FORGE_SERVER_PORT` 覆盖。不依赖外部 MySQL 与 Redis 的本机演示启动（内存库，含 H2 运行时依赖）：

~~~powershell
.\mvnw.cmd -B -pl forge-application -am -DskipTests install
java -jar forge-application\target\forge-application-1.0.0.jar --spring.profiles.active=standalone --server.port=18080
~~~

`standalone` profile 定义在 `application-standalone.yaml`，只用于本机验证接口与文档，不代表生产部署方案；内存库没有系统表，因此该 profile 关闭了初始管理员引导。

首次在空库上启动（M3 起）需要提供初始管理员凭据，否则启动会明确失败。当前开发与演示环境统一使用 `admin` / `admin`：

~~~powershell
$env:FORGE_INIT_ADMIN_USERNAME = 'admin'
$env:FORGE_INIT_ADMIN_PASSWORD = 'admin'
$env:FORGE_INIT_ADMIN_DISPLAY_NAME = '初始管理员'
java -jar forge-application\target\forge-application-1.0.0.jar
~~~

`admin` 只有 5 位，符合当前「5—64 个字符」的创建规则（2026-09-29 按用户要求由 8 位放宽）。这只适用于本机与演示环境，生产环境请在首次登录后通过管理接口改成更强口令。

引导只在 `sys_admin` 为空时创建账号并授予超级管理员角色，已有管理员时不做任何修改；不需要引导时设置 `FORGE_INIT_ADMIN_ENABLED=false`。

启动后可访问（M3 起受保护接口需要 Bearer 令牌，只有登录接口与文档路径匿名可达）：

~~~powershell
# 登录并取得令牌（用户名不区分大小写）
$login = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/login' `
  -ContentType 'application/json' -Body '{"username":"admin","password":"admin"}'
$token = $login.data.accessToken

# 当前身份与权限、当前菜单
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/me' -Headers @{Authorization="Bearer $token"}
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/menus' -Headers @{Authorization="Bearer $token"}

# 失败路径：密码错误返回 HTTP 200 + body.code=401；未带令牌访问受保护路径同样是 401
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/login' `
  -ContentType 'application/json' -Body '{"username":"admin","password":"wrong"}'
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/me'

# 退出后原令牌立即失效
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8080/api/admin/v1/auth/logout' -Headers @{Authorization="Bearer $token"}

# 示例接口与文档（示例接口不再是匿名路径，需带令牌；文档路径默认放行，文档只在开发 profile 开启）
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/api/admin/v1/example/hello' -Headers @{Authorization="Bearer $token"}
Invoke-WebRequest 'http://127.0.0.1:8080/v3/api-docs/admin' -UseBasicParsing
Invoke-WebRequest 'http://127.0.0.1:8080/swagger-ui/index.html' -UseBasicParsing
~~~

数据库迁移由 `forge-framework` 的 `FlywayConfig` 显式针对主库执行，只加载 `classpath:db/migration`，并遵循 `spring.flyway.enabled`。
M3 新增 `db/migration/system/V20260930120000__init_system_tables.sql`：在真实 MySQL 8.4 上执行成功，重复启动显示 `Schema is up to date. No migration necessary.`。
脚本目录说明见 `backend/forge-application/src/main/resources/db/migration/迁移说明.md`。

真实中间件探针（默认构建会跳过，用于确认核心组合）：


## 4. 前端

工作目录：`frontend`。

~~~powershell
cd frontend

pnpm install            # 首次或依赖变更后
pnpm run type-check     # 两个工作区包的严格类型检查
pnpm run lint           # ESLint 平坦配置
pnpm run test           # Vitest（公共请求包协议分流用例）
pnpm run build          # 后台管理前端与公共包的构建

pnpm run dev:admin      # 后台管理前端，http://localhost:5173
~~~

开发服务器默认把 `/api` 代理到 `http://127.0.0.1:8080`。公共默认值位于 `admin/.env`，用 `.env.local` 中的 `VITE_API_PROXY_PREFIX`、`VITE_API_PROXY_TARGET` 覆盖；端口冲突会明确失败，用 `VITE_DEV_PORT` 调整后重启，不要停止其他项目进程。Vite 配置已通过 `loadEnv` 读取这些文件。

接口基础地址来自后台管理前端的 `.env` 与 `.env.local`（模板为 `.env.example`），不写死域名。公共请求工厂在 HTTP 200 下仍检查 `body.code`：

- `code=0` 返回业务数据，`data` 为 `null` 表示该用例没有业务数据。
- `code=401/403` 触发对应钩子后再抛出，其余非零 code 触发统一错误钩子。
- 结构不符合协议按协议异常处理，连接、超时与代理错误按传输异常处理。

令牌读写、路由与账号状态属于前端应用自己，不进入公共包；公共请求工厂通过 `tokenProvider` 接收应用的令牌读取函数。M3 已实现登录页、路由守卫与权限菜单（只搭结构，视觉样式待设计确定后调整）：

- 登录后令牌写入 `sessionStorage`（键名 `orange-forge:admin:token`），受保护接口自动携带 `Authorization: Bearer <token>`。
- 受保护请求返回 `body.code=401` 时清理会话并跳转登录页；登录接口的 401 只提示凭据错误，不跳转。
- 侧边栏菜单来自 `/api/admin/v1/auth/menus`，并经过 `src/router/menu-routes.ts` 的白名单映射，未登记的标识不渲染。

~~~powershell
git config --local user.name OrangeNode

~~~

## V1 视频采集本地运行

依赖现有 MySQL/Redis，启动时自动执行视频表和菜单的两个新增 Flyway 迁移。重新启动后权限缓存刷新，新菜单无需手工重建角色。`standalone` 只用于文档与骨架预览，正式采集需真实依赖。

网络可以直连资源站时无需代理配置；本机验收使用部署环境提供的 HTTP 代理。需要代理时，在启动 Java 的同一终端设置无凭据代理 URL，不写入版本库：

~~~powershell
$env:FORGE_VIDEO_PROXY_URL = $env:HTTPS_PROXY
# 在 backend 目录；端口应按本机占用情况选择
java -jar forge-application/target/forge-application-1.0.0.jar --server.port=53698
~~~

管理端在 frontend 目录运行，代理指向同一后端：

~~~powershell
$env:VITE_DEV_PORT = '55074'
$env:VITE_API_PROXY_TARGET = 'http://127.0.0.1:53698'
pnpm run dev:admin --host 127.0.0.1
~~~

以上端口为本轮空闲端口示例，不是项目默认值。预置四站不自动采集；在分类映射弹窗使用“一键创建缺少分类并绑定”，配置缺失信息策略，再进行日范围小量检查，之后建立和启用定时任务。记录页可对勾选部分或筛选后的全部执行批量操作，确认范围及逐条结果。操作与验证记录见 [V1 视频任务](tasks/V1-视频采集与接口.md)。
