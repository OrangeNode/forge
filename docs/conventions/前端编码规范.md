# 前端编码规范

## 1. 工程与目录

`frontend/admin` 是唯一的 Vue 应用，拥有自己的环境、入口、路由、布局和状态。使用 pnpm workspace 管理，私有包使用 `@orange-forge/*` 且标记 private。

ESLint 平坦配置必须显式匹配源码目录（`admin/src/**/*.{ts,vue}` 与 `packages/*/src/**/*.ts`），根 `lint` 脚本传同样的路径：平坦配置只作用于被 `files` 匹配的文件，只写 `eslint .` 会让未被匹配的目录被静默跳过，出现“检查通过但其实没检查”。2026-09-30 修复了该缺口并加了验证。

~~~text
src/
├── api/              按业务划分请求方法
├── views/            按业务划分页面
├── components/       已被复用的公共组件
├── layouts/          当前应用布局
├── router/           静态路由与页面白名单
├── stores/           当前应用状态
├── composables/      可复用组合函数
├── types/            当前应用特有类型
└── utils/            小型纯工具
~~~

按实际需要创建。公共包 `frontend/packages/api-client` 仅包含协议、请求工厂及接口类型，不保存全局令牌、路由实例或账号 Store。

## 2. Vue 与 TypeScript

- Vue 3 使用 `<script setup lang="ts">`，启用 TypeScript strict。
- 组件名使用 PascalCase，组合函数使用 `useXxx`，API 函数明确动作与资源。
- 优先定义准确类型；不能用 any 掩盖接口错误，外部未知数据先校验再收窄。
- 手写具名业务函数使用中文多行说明；简单内联回调无需重复注释。
- 页面编排业务交互，API 文件组织请求，Store 只保存跨页面必要状态。
- 不构造万能表单、CRUD 引擎或大型工具集合；出现实际重复后提取公共组件。
- 两空格缩进，UTF-8 无 BOM，LF，格式与静态检查由统一配置约束。

## 3. 接口与类型

基础地址来自环境配置，不写死 `orangenode.cn`。共享请求工厂通过 `tokenProvider` 注入应用的令牌读取函数与错误处理钩子：公共包只把令牌写进 `Authorization` 头，不保存令牌，也不管理登录状态。

M3 已落地的接入方式：管理端在 `src/api/request.ts` 创建两个请求工厂——受保护接口用带 `onUnauthorized` 的实例（清理会话并跳转登录页），登录接口用不带该钩子的实例，避免凭据错误也触发跳转。令牌读取来自 `src/utils/session.ts`，键名 `orange-forge:admin:token`；未认证跳转经 `src/utils/navigation.ts` 注册，避免请求模块与路由模块互相引用。

所有 ID 为字符串，禁止 `Number(id)`、`parseInt(id)`。分页数字保持 number，不使用 ID 的字符串规则替代所有数值类型。

API 文档与类型生成在 M2 接入；生成代码标记来源，禁止手改生成结果。接口类型来自后端唯一的管理端分组，当前只生成 `admin`。M3 已按认证接口重新生成 `src/generated/admin.ts`，业务代码通过 `adminComponents['schemas'][...]` 引用，不复制协议类型。M1 骨架不伪造已存在的业务 API。

请求工具首先处理连接、超时和非预期 HTTP 响应等传输异常；收到应用 HTTP 200 的 JSON 响应后，必须读取 body.code。只有数字 code=0 才向页面返回成功数据，其他 code 转为包含 code、message、traceId 和可选字段错误的统一业务异常。即使请求库将 HTTP 200 放在成功回调中，也必须执行此检查。

缺失 code、非法响应结构或非预期非 JSON 内容作为协议异常处理，不默认当成成功。一次失败只出现一处用户提示。文件下载成功为二进制，失败可能也是 HTTP 200；依据响应 Content-Type 和错误结构识别 JSON 错误，不能把错误响应保存为文件。

## 4. 登录与权限

前端使用 `sessionStorage`，Key 包含项目标识；Key 命名不作为服务端身份隔离手段。Token 不进入 URL、日志或共享公共包。

以下分支判断的都是 body.code：受保护请求 code=401 时清理当前应用会话并进入对应登录页；登录接口 code=401 时显示凭据错误，不循环跳转。code=403 显示无权限，code=500 显示操作失败，code=503 提示稍后重试；这些情况不自动清空仍可能有效的会话。

后端菜单只引用本地路由白名单标识，不执行远程传来的组件代码。动态菜单与按钮检查使用同一份当前权限数据，但所有后端接口仍必须独立授权。

M3 已落地的菜单与路由约定：后端菜单的 `routeKey` 必须在 `src/router/menu-routes.ts` 的白名单中登记映射到本地路由名，未登记的节点不渲染；路由 `meta.public` 只用于登录页这类匿名入口，其余页面在进入前检查会话并读取一次身份与菜单。

2026-09-30 起的布局与标签约定：整屏高度固定为一屏（`height: 100vh`），侧边栏与顶栏不随页面滚动，只有菜单区与内容区内部滚动；每个管理页面用 `src/components/PageBody.vue` 作为根节点承担内边距与内部滚动，顶栏不展示页面标题与说明，路由 `meta.title` 保留供标签栏识别页面，页面内容区按需展示列表标题；所有管理列表页（含用户、角色、菜单、文件、存储配置、操作日志与登录日志）在白色卡片内使用 `PageHeader.vue` 展示列表名称、说明与操作区。侧边栏菜单的目录节点渲染为可折叠子菜单（`type: 'submenu'`）并默认展开，空目录不渲染；整条侧边栏可用顶栏按钮折叠为图标轨道。顶栏下方为多标签条（`src/stores/tabs.ts`）：进入页面即登记标签，最多保留最近 12 个（常驻标签为工作台，不可关闭），右键提供关闭当前/其他/左侧/右侧/全部；标签切换走正常路由跳转，不做页面缓存，避免标签里出现旧数据。

退出清除对应应用用户信息、权限、菜单与令牌。首版无自动刷新令牌，不编写递归重试登录逻辑。

## 5. 页面范围与体验

后台管理前端基于 Naive UI 自建轻量布局、菜单、表单、表格、对话框和结果页；首版只有登录页与后台管理页面，不开发面向普通用户的前台页面。

表单提供明确标签、字段错误、加载状态和防重复提交。用户输入使用文本渲染，不直接使用 `v-html` 输出未经处理内容。

在 375px、768px、1440px 下检查：登录表单可操作、页面无整体横向溢出、导航可收起、数据表格在局部容器滚动。日期按展示时区转换，提交带时区值，不把本地时间误标成 UTC。

## 6. 验证

M1 建立 ESLint、类型检查、构建及必要测试入口；M3 起接入真实认证，M5 验证公共页面。Vitest 覆盖 HTTP 200 下 code=0 与非零 code 的分流、协议异常、传输失败及有逻辑的组合函数；Playwright 覆盖登录、权限和响应式关键流程。

M4 与 M5 实际执行：管理端类型检查、ESLint、构建与 `scripts/check-frontend.mjs` 启动代理检查通过；`@orange-forge/api-client` 12 个 Vitest 用例（协议分流、令牌注入、查询参数过滤）与管理端 11 个 Vitest 用例（菜单白名单映射、失败提示与字段错误归集）全部通过。真实实例上验证了 401/403/404/409 分流与权限变更后的即时生效。未执行：浏览器内的三档宽度视觉检查与 Playwright 关键流程用例（本机没有可用浏览器环境），已记入 M5 任务第 4 节。

2026-09-30 复核：ESLint 修复了未覆盖 `admin/src` 的缺口后重新执行，类型检查、ESLint、构建与 Vitest（api-client 12 + 管理端 19，新增多标签状态 8 个用例）全部通过；Vitest 与 Vite 构建在受限沙箱下会因派生进程被拒（`spawn EPERM`）失败，需在放宽权限的终端执行，属执行环境限制。浏览器内的整屏布局、侧边栏折叠与三档响应式视觉验收仍未执行。

管理端当前约定：视觉以浅蓝色为主，浅蓝侧栏、浅灰蓝页面底色、白色无描边卡片和克制阴影；菜单悬停使用白底深蓝字，选中使用浅蓝底蓝字，任何状态都必须保持足够对比度；业务页面禁止使用渐变色。颜色与圆角集中在 `src/theme/calm-tech.ts`，页面不写死色值；下载统一走 `src/utils/download.ts`（识别 HTTP 200 的 JSON 错误体、解析 `filename*`）；失败提示统一走 `src/utils/error-message.ts`，一次失败只提示一次。菜单与权限在同一个页面维护：菜单区分目录/页面并从白名单选择图标，权限项同时编辑代码、中文名称和说明，角色授权只勾菜单节点、权限由节点推导，因此不再有独立权限页面。`NIcon` 只负责图标容器，项目的可选图标由 `AppIcon.vue` 白名单提供，不把任意组件名或 SVG 内容存入数据库。

失败或未运行的检查必须写进阶段任务。不会因为使用了模拟数据就把真实后端联调标记完成。

2026-09-30 页面简化约定：菜单与权限页采用左侧菜单树、右侧所选节点详情，树仅展示图标、名称与目录类型；操作与权限列表集中在详情区域。新增/编辑表单分为“基本信息”“接口权限”两个标签，切换保留输入与校验。文件列表、存储配置、操作日志与登录日志的搜索表单显式使用 `label-placement="left"`，标签和控件左右排列，窄屏筛选项可换行。

整屏高度使用 `100dvh`；主区域使用直接的 flex 容器，避免布局组件的默认滚动包装层破坏剩余高度分配。日志表格使用 `flex-height` 填满可用空间，筛选区与分页不随数据滚动，不通过固定的视口减值估算表格高度。

日志页卡片内容区布局选择器使用当前 Naive UI 实际类名 `.n-card-content`，修改内部组件布局时核对锁定依赖源码，不能仅凭类型检查或构建判断高度布局有效。


2026-09-30 菜单页细节调整：搜索输入框、查询与重置保持左右同排，按钮使用默认无填充样式，避免未操作时呈现选中观感；接口权限以名称、代码、说明三列紧凑列表展示，窄屏仅列表区域横向滚动。

2026-09-30 菜单详情操作区调整：新增子菜单、编辑与权限、删除由 tiny 文字按钮改为 38px 高、14px 字号的图标按钮，分别使用加号、编辑、删除图标；新增使用浅蓝底，编辑使用默认按钮，删除使用错误色描边。按钮间距 10px，空间不足时换行；保留原权限判断、删除确认及有子节点禁用规则。

后续管理页面必须沿用统一列表模板：`PageBody` → 白色 `NCard` → `PageHeader`（浅蓝图标、列表标题与说明、右侧操作）→ 筛选区 → 数据区 → 分页。头部按钮统一 `action-button` 类，由公共头部维护 40px 高度、10px 圆角与间距；刷新使用带图标的 primary secondary 按钮，新建/上传使用带图标的 primary 按钮。菜单页数据区可采用树与详情分栏，日志页数据区继续按剩余空间内部滚动；不再在卡片外另设独立操作行。头部不得参与日志表格的高度收缩。
