# 前端编码规范

## 1. 工程与目录

`frontend/admin` 是唯一的 Vue 应用，拥有自己的环境、入口、路由、布局和状态。使用 pnpm workspace 管理，私有包使用 `@orange-forge/*` 且标记 private。

~~~text
src/
├── api/              按业务划分请求方法
├── views/            按业务划分页面
├── components/       已被复用的公共组件
├── layouts/          当前应用布局
├── router/           静态路由与页面白名单
├── stores/           当前应用状态
├── composables/      可复用组合函数
├── types/            当前应用特有类型
└── utils/            小型纯工具
~~~

按实际需要创建。公共包 `frontend/packages/api-client` 仅包含协议、请求工厂及接口类型，不保存全局令牌、路由实例或账号 Store。

## 2. Vue 与 TypeScript

- Vue 3 使用 `<script setup lang="ts">`，启用 TypeScript strict。
- 组件名使用 PascalCase，组合函数使用 `useXxx`，API 函数明确动作与资源。
- 优先定义准确类型；不能用 any 掩盖接口错误，外部未知数据先校验再收窄。
- 手写具名业务函数使用中文多行说明；简单内联回调无需重复注释。
- 页面编排业务交互，API 文件组织请求，Store 只保存跨页面必要状态。
- 不构造万能表单、CRUD 引擎或大型工具集合；出现实际重复后提取公共组件。
- 两空格缩进，UTF-8 无 BOM，LF，格式与静态检查由统一配置约束。

## 3. 接口与类型

基础地址来自环境配置，不写死 `orangenode.cn`。共享请求工厂注入应用的令牌读取和错误处理逻辑。

所有 ID 为字符串，禁止 `Number(id)`、`parseInt(id)`。分页数字保持 number，不使用 ID 的字符串规则替代所有数值类型。

API 文档与类型生成在 M2 接入；生成代码标记来源，禁止手改生成结果。接口类型来自后端唯一的管理端分组，当前只生成 `admin`。M1 骨架不伪造已存在的业务 API。

请求工具首先处理连接、超时和非预期 HTTP 响应等传输异常；收到应用 HTTP 200 的 JSON 响应后，必须读取 body.code。只有数字 code=0 才向页面返回成功数据，其他 code 转为包含 code、message、traceId 和可选字段错误的统一业务异常。即使请求库将 HTTP 200 放在成功回调中，也必须执行此检查。

缺失 code、非法响应结构或非预期非 JSON 内容作为协议异常处理，不默认当成成功。一次失败只出现一处用户提示。文件下载成功为二进制，失败可能也是 HTTP 200；依据响应 Content-Type 和错误结构识别 JSON 错误，不能把错误响应保存为文件。

## 4. 登录与权限

前端使用 `sessionStorage`，Key 包含项目标识；Key 命名不作为服务端身份隔离手段。Token 不进入 URL、日志或共享公共包。

以下分支判断的都是 body.code：受保护请求 code=401 时清理当前应用会话并进入对应登录页；登录接口 code=401 时显示凭据错误，不循环跳转。code=403 显示无权限，code=500 显示操作失败，code=503 提示稍后重试；这些情况不自动清空仍可能有效的会话。

后端菜单只引用本地路由白名单标识，不执行远程传来的组件代码。动态菜单与按钮检查使用同一份当前权限数据，但所有后端接口仍必须独立授权。

退出清除对应应用用户信息、权限、菜单与令牌。首版无自动刷新令牌，不编写递归重试登录逻辑。

## 5. 页面范围与体验

后台管理前端基于 Naive UI 自建轻量布局、菜单、表单、表格、对话框和结果页；首版只有登录页与后台管理页面，不开发面向普通用户的前台页面。

表单提供明确标签、字段错误、加载状态和防重复提交。用户输入使用文本渲染，不直接使用 `v-html` 输出未经处理内容。

在 375px、768px、1440px 下检查：登录表单可操作、页面无整体横向溢出、导航可收起、数据表格在局部容器滚动。日期按展示时区转换，提交带时区值，不把本地时间误标成 UTC。

## 6. 验证

M1 建立 ESLint、类型检查、构建及必要测试入口；M3 起接入真实认证，M5 验证公共页面。Vitest 覆盖 HTTP 200 下 code=0 与非零 code 的分流、协议异常、传输失败及有逻辑的组合函数；Playwright 覆盖登录、权限和响应式关键流程。

失败或未运行的检查必须写进阶段任务。不会因为使用了模拟数据就把真实后端联调标记完成。
