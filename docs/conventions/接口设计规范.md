# 接口设计规范

## 1. 路径与身份

管理接口前缀为 `/api/admin/v1`，对应唯一的后台管理前端；App 接口前缀为 `/api/app/v1`，对应普通用户（2026-10-07 起）。两种身份的令牌按路径前缀分别识别，互不通用。路径使用小写资源名，HTTP 动词表达操作：

| 用途 | 示例 |
| --- | --- |
| 查询分页 | GET /api/admin/v1/notices |
| 查询详情 | GET /api/admin/v1/notices/{id} |
| 新增 | POST /api/admin/v1/notices |
| 完整修改 | PUT /api/admin/v1/notices/{id} |
| 状态修改 | PATCH /api/admin/v1/admins/{id}/status |
| 删除 | DELETE /api/admin/v1/notices/{id} |

上表的资源名与路径仅作示例，按实际业务替换。以上为接口约定，不代表这些路由已实现。URL 不包含域名常量。匿名访问逐个明确放行，未知路径不能默认放行。

## 2. 统一响应

`ApiResponse<T>` 位于 core，采用四个顶层字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| code | integer | 0 为成功；400、401、403、500 等表示失败类型，见下表 |
| message | string | 面向调用者的中文说明，不用于程序分支判断 |
| data | T 或 null | 成功结果、可选结构化校验详情；无数据为 null |
| traceId | string | 当前请求追踪标识，不用于认证 |

~~~json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "id": "123",
    "name": "示例名称"
  },
  "traceId": "9a8f57b847204291ae96670d2b963b58"
}
~~~

应用能够生成响应的 JSON 接口统一使用 HTTP 200，包括新增、修改、删除和异常响应。成功时 body.code 为 0；无业务数据时 data 为 null。前端必须读取 body.code，不能仅依据 HTTP 200 判定操作成功。

异常默认 `data: null`；参数错误可以提供 `data.fieldErrors`，每项只含 `field` 和 `message`，不得回显密码、令牌等被拒绝的原值。字段错误位于 `data` 之内，前端与后端都以该位置为准，不使用顶层 `fieldErrors`。M2 已实现的校验失败响应格式：

~~~json
{
  "code": 400,
  "message": "请求参数校验失败",
  "data": {
    "fieldErrors": [
      { "field": "nested.code", "message": "嵌套编码长度不能超过 4" }
    ]
  },
  "traceId": "9a8f57b847204291ae96670d2b963b58"
}
~~~

## 3. HTTP 200 与响应体状态码

下表中的数值均为响应体里的数字 code，HTTP 状态统一为 200。

| body.code | 语义 |
| --- | --- |
| 0 | 操作成功 |
| 400 | 参数、ID、分页、排序、JSON 格式错误 |
| 401 | 缺失、无效、过期令牌，或登录凭据无效 |
| 403 | 已认证但缺少权限 |
| 404 | 路径或可访问资源不存在 |
| 405 | HTTP 方法不支持 |
| 409 | 唯一约束冲突、状态冲突 |
| 413 | 上传内容超过允许大小 |
| 415 | 请求媒体类型不支持 |
| 429 | 请求触发限流 |
| 500 | 未预期的内部错误 |
| 503 | Redis、数据库或存储等必要依赖暂不可用 |

code 采用表中的数字状态语义，不再按模块分配六位错误码。同类错误通过中文 message 说明，程序分支只依据 code，不匹配 message 文案。若未来确需细分业务码，先扩展规范并同步调用方。

例如令牌失效时，HTTP 状态仍为 200，响应体如下：

~~~json
{
  "code": 401,
  "message": "登录已失效，请重新登录",
  "data": null,
  "traceId": "9a8f57b847204291ae96670d2b963b58"
}
~~~

业务异常、Validation、数据库唯一冲突和未知异常分别映射到 body.code。未知异常使用 code=500 和一般错误说明，不泄漏内部细节。Security 的 AuthenticationEntryPoint、AccessDeniedHandler 与 ControllerAdvice 复用统一错误写出组件，均写出 HTTP 200 和相应 JSON 错误码；不能使用 sendError、登录重定向或异常状态注解绕过该约定。

M2 已落地的错误出口分工（实现见 `cn.orangenode.forge.framework.web.error`）：

| 来源 | 覆盖场景 | 组件 |
| --- | --- | --- |
| DispatcherServlet 内 | 业务异常、请求体与方法参数校验、JSON 解析、类型不匹配、参数缺失、上传超限、媒体类型、方法不支持、静态资源未找到、唯一与完整性约束、Redis 与数据访问失败、未注册数据源、未知异常 | `GlobalExceptionHandler` |
| 过滤链 | 未认证（401）与无权限（403） | `SecurityErrorHandler`（认证入口与拒绝访问处理器共用） |
| 容器与框架 | 进入 DispatcherServlet 前后由容器产生的错误，经 `/error` 转发 | `UnifiedErrorController` |

三者复用 `WebErrorWriter` 写出 HTTP 200 与四字段响应体，追踪编号与 `TraceIdFilter` 写入的响应头一致；错误响应声明 `application/json;charset=UTF-8`。

框架可处理的路径不存在、方法不支持、类型绑定、JSON 解析及上传失败也纳入统一处理，覆盖默认错误出口。鉴权或校验失败必须立即终止原业务执行；返回 HTTP 200 不代表放行。

连接失败、超时及代理自身生成的错误可能没有应用响应体，前端将其作为传输异常处理，不能假造 code=0。文件流已开始后无法重新生成响应，按文件章节处理。

## 4. ID、时间与分页

- 路径、查询、请求体、响应体中的 ID 都为字符串；OpenAPI 同样声明 string。
- 对外 ID 只接受正十进制整数且不超过 Long 上限；非法格式及溢出返回 HTTP 200、body.code=400。
- 不依赖“后端序列化为字符串、OpenAPI 仍是 int64”的不一致方案。
- 时间使用带时区的 ISO 8601，例如 `2026-09-14T02:00:00Z`；持久化按 UTC。
- 枚举使用明确、稳定的代码，不返回依赖排序位置的枚举序号。

`PageRequest` 位于 framework 的 Web 入参包，可包含 Validation 注解；`PageResponse<T>` 位于 core，保持框架无关。

分页默认 `pageNum=1`、`pageSize=20`，页码必须大于等于 1，每页 1—100。排序字段按当前接口白名单映射，禁止拼接用户提供的 SQL 片段。

M2 已落地的分页约定（代码见 `cn.orangenode.forge.framework.page`）：入参统一使用 `PageRequest`（页码、每页条数与配置上限校验），业务查询用它的页码与条数构造 MyBatis-Plus 的 `Page`，返回时用 `PageResponses.from(...)` 转成 `PageResponse`，接口层不得出现 `IPage`、查询包装器或 Entity。

**排序白名单推迟实现**：`sortBy`/`sortDirection`、排序白名单与稳定排序在 M2 未实现——当时没有任何真实列表接口需要排序，提前引入的白名单映射与分页条件类型属于无使用者的抽象，已按“不为推测中的需求预建抽象”撤回。第一个真正需要排序的列表接口出现时，再按该接口的字段集合设计白名单映射，并补齐“非法字段返回 400”“非默认列排序时追加主键稳定排序”的验证。

~~~json
{
  "code": 0,
  "message": "操作成功",
  "data": {
    "records": [],
    "total": 0,
    "pageNum": 1,
    "pageSize": 20
  },
  "traceId": "9a8f57b847204291ae96670d2b963b58"
}
~~~

空页与超过最后一页返回空数组和真实 total，不返回 null。禁止直接返回 MyBatis-Plus IPage、Wrapper 或 Entity。

## 5. 参数校验

新增、修改、分页分别使用 Request 类型。字符串长度、必填、格式、集合大小采用 Validation；嵌套对象显式触发嵌套校验。关联存在性、状态转换和唯一性属于 Service 规则，并通过数据库约束处理并发冲突。

参数检查不能只依赖前端。允许写入字段必须显式声明，客户端不能设置创建人、账号身份、权限列表等服务器控制字段。

未知字段与可选字段的兼容策略在具体 DTO 中明确；不通过全局“忽略一切错误”掩盖类型不匹配。

## 6. 认证契约

| 身份 | 接口 | 匿名 |
| --- | --- | --- |
| 管理员 | GET /api/admin/v1/auth/captcha | 是 |
| 管理员 | POST /api/admin/v1/auth/login | 是 |
| 管理员 | POST /api/admin/v1/auth/logout | 否 |
| 管理员 | GET /api/admin/v1/auth/me | 否 |
| 管理员 | GET /api/admin/v1/auth/menus | 否 |

登录返回 `accessToken`、`tokenType: Bearer`、`expiresIn`（秒）及当前管理员的基础信息。默认 7200 秒，固定有效期；首版不提供刷新接口。

M3 已落地的认证细节（实现见 `cn.orangenode.forge.framework.security` 与 `cn.orangenode.forge.system`）：

- **用户名规范化**：保存与查询前统一去首尾空格并转小写，登录因此不区分大小写，也不会出现 `Admin` 与 `admin` 两个账号；长度规则集中在一处（4—32 个字符），不在各 Controller 各自定义。
- **密码规则**：创建与改密要求 5—64 个字符；登录只校验非空与长度上限，避免历史密码因后来的强度规则而无法登录。只保存编码结果，接口与日志都不回显密码。2026-09-29 按用户明确要求把最小长度由 8 位放宽到 5 位：初始管理员与演示环境使用 `admin` 这类口令；弱口令只允许出现在初始引导与演示环境，生产环境应通过管理接口改成更强口令。
- **失败提示与限流**：账号不存在、密码错误、账号已停用返回同一 `body.code=401` 与同一句提示，不暴露账号是否存在；同一用户名在统计窗口内失败次数达到上限后返回 `body.code=429`，阈值与窗口来自 `forge.security.*`，登录成功清零计数。同一来源地址的失败另行计数（管理员与普通用户分开），达到 `login-ip-max-attempts` 后同样返回 429，登录成功不清零（2026-10-09）。
- **图形验证码**（2026-10-09）：管理员登录前先 `GET /auth/captcha` 取 `captchaId` 与 PNG data URL，登录时提交 `captchaId`、`captchaCode`；验证码两分钟有效、不区分大小写、无论对错只能用一次，缺失或错误返回 `body.code=400`，只计入来源地址失败次数、不计入账号失败次数。`forge.security.captcha.enabled=false` 时接口返回 `enabled=false`，只用于自动化测试。
- **未知路径**：未认证访问未知路径返回 401（先认证），认证通过后才由框架错误出口给出 404；未知路径不会默认放行。
- **当前身份与菜单**：`/auth/me` 返回当前管理员的 ID、用户名、显示名称与实时解析的权限代码；`/auth/menus` 返回按当前管理员解析的菜单树，`routeKey` 为前端本地路由标识，目录节点为空。菜单节点同时声明接口权限：`/auth/me` 给出的权限代码正是该管理员可见菜单节点上声明的标识并集（2026-09-30 调整，此前菜单可见性与接口权限分开解析）。
- **超级管理员语义**：按 `forge.security.super-role-code` 识别的角色拥有全部有效权限与全部有效菜单，不需要逐条建立关系；空库安装后由初始化引导创建的管理员因此可以管理工作台自身。
- **文档路径**：`/v3/api-docs/**`、`/swagger-ui/**` 在匿名放行列表中，文档本身默认关闭、只在开发 profile 开启；需要在受保护环境保留文档时，把文档路径移出匿名放行列表并改由令牌访问。

管理员不提供注册接口：由初始化流程或有权限的管理员创建，无公开注册。普通用户认证契约见本文末“App 普通用户与观看授权”（2026-10-07 起）。

受保护接口通过 `Authorization: Bearer <token>` 认证。令牌为 256 位随机值，服务端只在 Redis 保存摘要与账号会话版本；退出只撤销当前令牌，停用与改密按账号递增会话版本，使此前签发的全部令牌在下一次请求即失效。

`@PreAuthorize` 使用 `模块:资源:动作` 权限码，例如 `system:role:update`。前端菜单权限不替代后端检查；当前用户 ID 从安全上下文获取。方法级权限拒绝与过滤链拒绝都写出 `body.code=403`，`data` 为 `null`。

M5 已落地的系统管理接口（`cn.orangenode.forge.system.controller.admin`）：`/api/admin/v1/system/admins`、`/roles`、`/menus` 三组资源，权限码为 `system:admin:*`、`system:role:*`、`system:menu:*`（清单见迁移 `V20260930170000`）。行为约定：用户名规范化后唯一，冲突 409；密码按创建规则校验并编码保存，重置密码与停用都会撤销该账号全部令牌；账号启停使用条件更新，状态未变化返回 409，且不允许停用当前登录账号；角色被管理员引用、菜单有子节点或被角色引用时删除返回 409；内置超级管理员角色不允许删除或改代码；所有写接口记录操作审计。

2026-09-30 调整：权限改为菜单节点上的 `permissions` 对象列表，每项包含 `code`、中文 `name` 与可选 `description`；菜单请求同时提交 `menuType`（`directory`/`page`）和图标标识 `icon`，菜单响应原样返回这些元数据。角色授权只提交 `menuIds`，角色详情返回的 `permissionCodes` 由已授予菜单推导，不可单独提交；权限代码全局唯一，格式或中文名称非法时返回 400，并把 `permissions[index].字段` 写入 `data.fieldErrors`，被其他节点占用返回 409。`permCodes` 暂作为旧客户端兼容字段保留，新客户端不得使用。`/system/permissions` 独立权限管理接口随权限页面一并退出范围，`system:permission:*` 权限码不再存在。

权限解析在 M5 改为带全局版本的缓存：缓存键为 `auth:perm:v{版本}:{管理员ID}`，存活时间来自 `forge.security.permission-cache-ttl-seconds`；任何角色、菜单权限标识、管理员角色关系变更在事务提交后递增版本，使全部既有缓存立即失效，不使用通配扫描。Redis 不可用时受保护请求返回 503，不放行也不降级。

## 7. 文件与审计

上传使用 multipart/form-data，返回文件 ID 和安全元数据，不返回本地绝对路径或存储密钥。客户端下载按文件 ID 发起，服务端校验访问权限。

下载成功使用 HTTP 200 返回二进制流，设置安全的文件名与 Content-Disposition（中文名使用 RFC 5987 的 `filename*`），并声明 `X-Content-Type-Options: nosniff`。错误发生在流开始前时同样返回 HTTP 200，但 Content-Type 为 application/json，响应体包含非零 code。前端下载封装先识别约定的 JSON 错误响应，再把成功二进制作为文件处理，不能把错误 JSON 保存成文件。流开始后出错则记录追踪信息并终止传输，不再拼接 JSON。

M4 已落地的文件接口（`cn.orangenode.forge.file.controller.admin`，权限码见迁移 `V20260930140000`）：

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/v1/files` | 按文件名筛选的分页查询，只返回元数据与上传者快照 |
| `POST /api/admin/v1/files` | multipart 上传（字段名 `file`）；扩展名与大小校验失败返回 400，超过方案上限返回 413，尚未配置默认方案返回 404 |
| `GET /api/admin/v1/files/{id}/download` | 按文件 ID 下载，成功为二进制流，失败为统一 JSON |
| `DELETE /api/admin/v1/files/{id}` | 先清理对象再逻辑删除；对象清理失败返回 503，不报告成功 |
| `POST/DELETE /api/admin/v1/files/{id}/public-link` | 生成（已公开时返回原链接）或撤销公开外链，权限 `file:record:share`；响应 `publicUrl` 不含域名（2026-10-08） |
| `GET /api/public/v1/files/{令牌}/{文件名}` | 匿名下载公开文件，只按令牌查找；支持单段 `Range: bytes=起-止`（206 + `Content-Range`，越界 416）；令牌无效或已撤销返回 HTTP 200 + code=404 |
| `GET/POST /api/admin/v1/storage-configs`、`PUT/DELETE /{id}`、`POST /{id}/test`、`PUT /{id}/default` | 存储方案版本化维护、连接检测与默认切换；被文件引用的版本修改或删除返回 409 |

审计记录使用动作、资源 ID、业务结果 code、身份类型及 traceId；成功与失败以业务 code 判定，不能因为 HTTP 200 全部记录成功。接口层不把完整请求体和响应体默认写入审计。

M4 已落地的审计实现：`@AuditOperation`（写接口）+ `@AuditResourceId`（对象 ID 参数）由 `AuditOperationAspect` 记录，切面的结果码映射与响应侧保持一致（业务异常取自带码、权限拒绝 403、唯一键或完整性冲突 409、Redis 与数据源连接失败 503、其余 500）。查询接口为 `GET /api/admin/v1/audit/login-logs` 与 `GET /api/admin/v1/audit/operation-logs`，时间范围必须是带时区的 ISO 8601，否则返回 400；不支持排序参数，排序固定为时间倒序加主键倒序。

## 8. OpenAPI 与兼容性

管理接口按 admin 分组，公开视频 GET 按 app 分组；每个接口说明中文用途、请求示例、字段校验和权限。在 HTTP 200 响应下分别给出成功与异常的 body 示例、code 含义和对应数据结构，不能把业务错误只声明为非 200 HTTP 响应。下载同时声明二进制成功与 JSON 错误，ID 声明字符串。

M2 已落地：`OpenApiConfig` 装配唯一的 admin 分组（`/api/admin/**`），声明中文说明与 `bearerAuth` 方案；控制器中的对外 ID 使用字符串类型，文档 schema 因此为 `string`，不允许“后端字符串、文档 int64”。类型生成工具与命令见[本地开发指南](../本地开发指南.md)的接口类型生成一节，生成结果纳入前端类型检查。

开发环境启用 Swagger UI 和规范导出；生产默认关闭两者。自定义开启时也必须保护文档访问，不影响业务接口权限。

同一 v1 下优先新增可选字段，不重用旧字段表达不同含义。破坏性变更先更新规范和调用方任务；不在各端复制不一致的协议类型。

## 9. 验收要求

- 成功查询、新增、修改、删除均断言 HTTP 200 且 body.code=0。
- 参数错误、未登录、无权限、不存在、冲突、限流、内部异常、依赖不可用等场景均断言 HTTP 200 且 body.code 为对应非零值。
- 分别验证 ControllerAdvice、Security 过滤链和框架默认错误出口，确认异常后业务没有继续执行。
- 前端收到 HTTP 200、body.code=401/403/500/503 时进入对应失败流程，不返回成功数据；传输异常单独处理。
- 下载的二进制成功、JSON 失败和流中断分别验证；审计不得将非零 code 记为成功。

## 视频 App 只读例外

> 2026-10-07 起本节的匿名范围已收回：四个视频 GET 必须普通用户登录，播放线路另需观看授权并只返回 M3U8/MP4，见本文末“App 普通用户与观看授权”。以下为 V1 当时的口径，其余规则（排除下架影片、停用分类与线路，限流 429、依赖故障 503）继续有效。

只允许匿名 GET `/api/app/v1/video/categories`、`/videos`、`/videos/{id}`、`/videos/{id}/play-lines`。安全配置 `forge.security.public-get-paths` 按方法匹配，不能把整个 App 前缀加入无条件匿名列表。管理配置与写请求继续认证，业务读查询排除删除/下架影片、停用分类及祖先和停用线路。列表不带分集，播放地址单独返回，来源声明集数与实际地址数分开。限流返回 HTTP 200、body.code=429，依赖故障遵循现有 503 协议。

管理视频资源使用 `/api/admin/v1/video/**` 和菜单声明的 `video:*:*` 权限。供其他页面使用的分类、来源和候选影片查询允许相关业务查看/确认权限之一；写操作仍要求本资源操作权限。请求、响应和操作清单由 OpenAPI admin/app 分组生成，前端生成二者类型；业务规则见 [V1 任务](../tasks/V1-视频采集与接口.md)。

视频分类自动映射 `POST /sources/{id}/categories/auto-map` 复用来源编辑权限，`createMissing=true` 同时要求分类编辑权限。记录批量操作 `POST /runs/batch` 与 `POST /pending/batch` 明确部分或全部筛选范围；合法请求返回 `total/succeeded/failures`，body.code=0 表示批量请求已处理，前端仍须展示逐条失败，不能提示所有条目成功。运行与待确认分别要求运行操作与确认权限；动作、空勾选和单条状态冲突由服务端校验。

- **令牌**：登录与注册返回 `accessToken`、`tokenType: Bearer`、`expiresIn`（秒，默认 2592000）。有效期为滑动有效期，距上次续期超过 `forge.member.auth.renew-interval-seconds` 的请求会重置为完整有效期；Redis 键为 `member:session:{摘要}`，与管理员 `auth:session:` 分开。
- **隔离**：`forge.member.auth.path-prefix`（默认 `/api/app/`）下只识别普通用户令牌，其余路径只识别管理员令牌；普通用户令牌访问管理接口、管理员令牌访问 App 受保护接口均为 401。
- **撤销**：退出只撤销当前令牌；停用、后台重置密码、修改密码与“全部设备下线”递增数据库 `member_user.session_version`，此前令牌在下一次请求失效。
- **设备**：登录与注册必须提交 `deviceCode`（App 首次安装生成，8—64 位字母数字、下划线或连字符）与 `deviceName`；同一设备重复登录只替换该设备令牌。在线设备达到功能开关 `maxDevices` 时踢出最早登录的设备（离线原因 LIMIT）；设备名称与 IP 只作展示。
- **用户名**（2026-10-08 起取代邮箱）：不经过邮箱验证；忘记密码由管理员在后台“会员管理”重置；后台列表与登录设备按用户名关键字筛选，响应字段为 `username` / `memberUsername`。
- **搜索**：`/api/app/v1/video/videos` 的 `keyword` 按片名包含匹配；若关键字只由 1—32 个字母数字组成，同时按片名拼音首字母前缀匹配（如 `qyn` 找到《庆余年》），供电视遥控器字母键盘使用（2026-10-08）。
