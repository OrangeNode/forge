# A7-续费并发与体验修复

2026-10-09 用户反馈五个问题，要求修复后发布新版本：开屏广告前闪一下别的界面；手机与电视会员中心要能用激活码续费；“会员状态已刷新”这类提示不要贴在底部，改到屏幕中间；视频播放失败的提示卡在画面中间不消失（视频加载好后又继续播放）；采集要能多个资源站同时跑。App 界面在 `orange-app` 仓库，本文件记录后端、管理端、App 与发布结果。

## 1. 改动与原因

| 问题 | 原因 | 改动 |
| --- | --- | --- |
| 开屏前闪一下 | 系统启动窗口只有 logo；Flutter 接手后先画“logo 上移 + 文字 + 转圈”的等待页，广告图下载完之前还显示灰色占位图；Android 12 起系统启动画面默认是白底大图标 | App 等待期间只画与启动窗口完全相同的深色底 + 96dp logo（`LaunchBrand`），首帧推迟到 logo 解码完成；广告图预先下载解码好才显示，3 秒（`SPLASH_IMAGE_TIMEOUT_SECONDS`）内没好就不显示广告直接进入；新增 `values-v31`/`values-night-v31` 让 Android 12+ 系统启动画面也用深色底与同尺寸 logo；App 启动即铺满到导航栏下方，logo 不上下跳 |
| 激活码续费 | 原来只有注册能用激活码 | 新接口 `POST /api/app/v1/member/profile/activation`：已登录用户输入激活码，时长接在当前 VIP 到期时间之后，已过期或未开通从现在起算；与注册共用同一批码、一码一次，输错计入来源地址每日失败次数；不含会员时长的旧码拒绝且不核销。迁移 `V20261009120000` 给激活码加 `used_for`（REGISTER/RENEW，已使用的旧数据回填 REGISTER）。后台激活码列表与导出增加“用途”列。App 手机会员中心加激活码输入框，电视“设置 → 其他”加“激活码续费”页 |
| 提示贴在底部 | 手机用 SnackBar、电视用底部浮动 SnackBar | 两端统一改为屏幕中间的圆角提示（`showCenterToast`），约 2 秒淡出，新提示替换旧提示，不拦截触摸与遥控器按键；原 `showSnack`/`showTvToast` 调用处不变 |
| 播放失败提示卡住 | 播放器（mpv）在个别分片或某次连接失败时也会报错，但会自行重试继续播放；App 把每次报错都当成彻底失败，提示一直挂着直到换集，手机端还会误切线路 | 报错后先观察 8 秒（`PLAY_ERROR_GRACE_SECONDS`），画面继续前进就当已恢复；确认失败才提示（手机仍自动换线路）。提示出现后画面又前进 2 秒以上自动收起；手机提示带关闭按钮，电视按返回键先关提示再退出播放 |
| 采集只能一个个跑 | 执行器是单线程，队列逐个运行 | 不同资源站的运行并发执行，同时运行数不超过后台“视频采集设置 → 最大并发采集数”（迁移 `V20261009120100`，默认 3，上限 `forge.video.max-concurrency-limit` 默认 8）。同一资源站同一时刻仍只有一个活动运行（排队时已保证），按页顺序采、断点照旧；一个结束立即补位。网络请求与解析并发，入库仍逐页在全局锁内提交，避免两个站同时写入同名影片时重复建片 |

取舍：

- 续费复用激活码而不是另做兑换码，后台不必管理两套码；用途写在激活码上即可追溯。
- 并发只放在资源站之间，单站内部不并发翻页，避免被源站限流，也不改变断点语义；入库串行是因为去重依赖“看得到已提交的同名影片”，入库本身很快，耗时主要在网络与每页间隔。
- 播放报错的观察时间对“地址根本打不开”的情况也适用，代价是这类失败要约 8 秒才提示或换线路。
