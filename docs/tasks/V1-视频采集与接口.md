## 数据裁剪与规则

使用影片 → 来源记录 → 播放线路 → 分集四层结构。影片保留名称、分类、年份、地区、语言、导演、演员、封面、纯文本简介、更新说明、源站总集数及完结标志；来源保留匹配快照和源更新时间。播放 URL 保存完整参数及编码，类型区分 M3U8、MP4、OTHER。实际地址数量逐线路返回 `availableEpisodeCount`，不当作源站 `declaredTotal`，完结未知保持 null。

网站模板、SEO、标题颜色、拼音索引、多套封面、积分密码试看、点击点赞评分、下载地址、文章和分集剧情不纳入首版。封面仅保存远程 URL，不下载视频或播放内容。

同站先查资源站+站内影片 ID；跨站名称必选，默认名称+年份+映射后本地分类，选中条件全部相等才合并。仅统一空白、大小写和全半角，导演演员按人员集合比较。缺失信息按字段策略进入待确认、跳过或允许为空；允许为空的去重字段缺失时独立新建影片，不减弱条件跨站合并。多候选始终待确认，不去掉季数、不模糊匹配。待确认展示源站资料及候选；自然重采补齐字段仍保留待确认，管理员可显式批量按最新规则采集入库。忽略及删除决定在重采和日志清理后保持有效。

首次新建的来源成为主要来源。主要来源按设置覆盖非空资料；非主要来源只更新自己的地址。人工编辑默认锁定资料，锁定不阻止地址更新。人工编辑和采集更新使用同一影片行锁，避免并发覆盖。每条完整解析成功的非空线路替换分集；失败、空结果和其他来源不清空旧地址，停用线路不自动恢复。下架及逻辑删除也不因重采恢复。

## 任务行为

范围只支持 DAY（24 小时）、WEEK（168 小时）和 ALL（不限制更新时间）。后台可展示及复制具体源请求 URL，链接只是请求预览，没有匿名执行入口。

执行时间使用标准五段 cron（分 时 日 月 周），按统一调度时区 `forge.video.default-zone`（默认 Asia/Shanghai）解释，不再按任务设置频率与时区；数据库时刻为 UTC，接口返回带时区时间。新任务默认停用，可在新建或列表中直接启用，启用前检查有效来源与已配置映射。修改后重新计算下一次时间。迁移 `V20261007100000` 将旧的 INTERVAL/DAILY/WEEKLY 设置换算为等价 cron。

队列适用于单实例。同站活动运行通过来源行锁和状态检查防重叠，全局执行器顺序处理。网络和解析在页面事务外，整页成功才移动断点，重复提交旧页不重复计数。停止在当前页事务后生效；重启的活动运行标为中断，管理员可继续。停机错过计划最多补触发一次，超过滚动窗口给出周/全量补采提示。断点不是源站数据快照，源站翻页内容可能变化。

源站数据不可控，单条影片的数据异常不阻断采集（2026-10-09 用户要求）：整页结构错误（非成功码、JSON 无法解析、分页矛盾）仍拒绝该页并保留断点；单条影片的线路数与地址组数不一致、线路标识为空或重复、分集缺少地址、字段超过存储长度等，解析时跳过异常部分（超长字段截断）并记录原因，该影片转入待确认（原因以“源站数据格式异常：”开头），同页其他影片照常入库；人工确认可用保留下来的线路入库。缺少来源编号的影片无法追踪，计为跳过。只有地址没有名称的分集不算异常，按位置命名，单集线路命名为“正片”。

结束日志按保留天数清理；未处理待确认保留运行引用，已忽略记录保留身份但可解除过期运行引用。源码不记录完整上游响应、完整播放地址或接口凭据到日志。

## 配置与操作

网络默认连接 10 秒、请求 30 秒、间隔 1 秒、额外重试 2 次、响应上限 10 MiB；扫描 5 秒、历史记录 30 天、清理间隔 24 小时。全部在 `forge.video.*` 配置，App 默认每连接 IP 每 60 秒 120 次。代理网关部署时应让应用收到可信的真实客户端地址，否则共享出口会共享限额。

请求使用可配置的 `forge.video.user-agent` 明确标识采集器；视频 Mapper 日志默认 INFO，避免输出 URL 参数和原始数据。前端分页、轮询、新增资源站默认时区及新任务默认 cron 来自五项 `VITE_VIDEO_*` 配置。

可选 `FORGE_VIDEO_PROXY_URL` 只用于部署网络，格式为无凭据的 HTTP 代理地址及端口；默认空值直接访问。采集使用 HTTP/1.1，不跟随跳转，资源站必须使用最终公网 JSON 地址。地址检查拒绝内网、非 HTTP 和 URL 内嵌凭据。播放地址仅存储，不会被采集服务请求。

使用顺序：

1. 重启连接真实 MySQL/Redis 的应用，由 Flyway 建表与菜单。
2. 资源站分类映射中读取分类，再点击“自动识别并绑定”或“一键创建缺少分类并绑定”；后者在首次没有缓存时会先读取分类。已有手工映射保持不变，歧义或停用分类按统计提示处理。
3. 用日范围、明确的源分类做小范围手动采集，在记录查看进度及待确认。
4. 确认资料与线路后建立定时任务，检查映射再启用。
5. App 使用公开列表与详情；需要分集时单独请求播放线路。

独立 `standalone` profile 的 H2 不执行 MySQL Flyway，也不初始化采集业务数据，适合文档生成；正式功能需连接真实依赖。

## 接口

管理前缀 `/api/admin/v1/video`。资源包括 categories、sources、videos、settings、tasks、runs、pending。任务提交 `POST /tasks/collect` 立即返回运行资料和字符串运行 ID，运行状态通过 `GET /runs/{id}` 查询；停止和继续分别 `POST /runs/{id}/stop`、`POST /runs/{id}/resume`。具体请求模型和权限以 OpenAPI admin 分组为准。

公开四个接口：

| GET 路径 | 返回内容 |
| --- | --- |
| `/api/app/v1/video/categories` | 本地有效分类树 |
| `/api/app/v1/video/videos` | 影片分页，支持关键词/分类/年份/地区/语言 |
| `/api/app/v1/video/videos/{id}` | 已上架影片资料，不含管理配置 |
| `/api/app/v1/video/videos/{id}/play-lines` | 启用线路、实际地址数和完整分集地址 |

公开内容要求影片未删除、已上架、分类及其祖先启用；写请求和未知路径依旧保护。HTTP 200、四字段响应、字符串 ID 和分页沿用既有规范，限流 body.code=429；Redis 故障不绕过限流。

### 自动分类

分类映射弹窗增加自动识别及一键创建并绑定。先匹配规范化名称，再匹配常见后缀（片、剧、劇、类、類）；唯一有效候选才能绑定，多候选、停用、缺少父节点及循环关系留待人工确认。创建按源父子顺序进行，已有映射保持不变，不迁移历史影片的分类。操作返回新建数、新增绑定数、保留数及未解决编号。

接口 `POST /sources/{id}/categories/auto-map` 接受 `createMissing`。绑定要求 `video:source:edit`；创建同时要求 `video:category:edit`。操作在短事务中串行化分类创建，来源刷新与手工绑定使用同一来源锁。

### 缺失信息

`settings.missingPolicies` 按名称、分类、播放地址、年份、地区、语言、导演、演员、封面、简介分别保存 `PENDING`（待确认）、`SKIP`（跳过）、`ALLOW`（允许为空）。新影片的名称、有效分类和播放地址不允许 `ALLOW`。多项缺失时跳过优先，其次待确认；允许为空不清除已有资料。未配置字段保持原有语义：新来源的去重字段及必要信息待确认，其余资料允许为空；已关联来源保留旧资料和线路，但显式字段策略仍生效。

新运行保存策略快照，设置变更不会改变活动运行或旧断点规则。没有名称的来源数据交给策略处理；没有来源编号仍拒绝解析。允许为空的去重资料缺失时不自动匹配已有影片，同站身份继续保证幂等。历史设置与旧 JSON 快照不含该字段时兼容原行为。

### 批量记录

运行与待确认表格增加勾选、“操作勾选部分 / 操作筛选后的全部”、操作选择及结果弹窗。全部范围由服务端筛选，包含所有分页；执行前显示目标数量和实际动作，执行后显示成功数及每条失败原因。每条独立事务，不把部分成功描述为全部成功。

- `POST /runs/batch`：`COLLECT` 按原来源/范围重新排队并使用最新规则；`STOP` 请求停止；`DELETE` 只删除终态历史并解除待确认的运行引用，活动运行拒删。重新采集不改变原运行记录，同站活动采集仍阻止重复排队。
- `POST /pending/batch`：`COLLECT` 用来源快照和最新规则重新判断，仍缺少必要信息或有匹配歧义时返回原因、保留待确认；`DELETE` 移出列表并保留 `DELETED` 来源身份，后续重采不恢复。已入库影片不受记录删除影响。
- 请求明确 `scope=SELECTED/ALL`、`ids`、`status`，待确认支持可选 `runId`；空勾选返回 400。两类操作分别复用 `video:run:operate` 和 `video:run:resolve`，保留审计与统一响应协议。
