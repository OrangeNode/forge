## 3. 实际交付

### 后端（M1-T02）

`backend` 为 Maven 多模块父工程，继承 `spring-boot-starter-parent:4.1.1`，Java 21，UTF-8。
八个模块与依赖方向与架构文档一致：core → framework → system / member / file / audit / example → application。
`forge-application` 是唯一可执行模块，`mvnw.cmd` 固定 Maven 3.9.16。

已实现的真实代码（不含占位）：

| 位置 | 内容 |
| --- | --- |
| forge-core | `ApiResponse`（四字段统一响应、追踪编号、成功/失败工厂）、`ErrorCode`、`PageResponse` |
| forge-framework | `TraceIdFilter`（追踪编号写入请求属性与响应头）、`JacksonConfig`、`ForgeWebProperties`、`PageRequest`（Jakarta Validation）、`FlywayConfig`（显式针对主库迁移） |
| forge-example | `HelloController`（`GET /api/admin/v1/example/hello`）与 `HelloResponse` |
| forge-application | `ForgeApplication`、`application.yaml` 与 local/test 覆盖、`db/migration/迁移说明.md` |

未创建空 Controller、空 Mapper 或业务表。system、member、file、audit 目前只有 POM，等对应阶段按需求创建实际代码。

### 依赖服务（M1-T03）

按用户指示部署到服务器 `172.16.112.183` 家目录 `~/orange-forge`（Ubuntu 24.04，Docker 29.4.3，Compose v5.1.3）：

| 服务 | 镜像 | 宿主端口 | 命名卷 |
| --- | --- | --- | --- |
| MySQL | mysql:8.4.11 | 3307 → 3306 | orange-forge-mysql-data |
| Redis | redis:8.10.1-alpine | 6380 → 6379 | orange-forge-redis-data |

服务器 3306 已被另一项目的 MySQL 占用，因此本项目改用 3307 与 6380，未停止或改动他人容器。
MySQL 使用 utf8mb4、`+00:00`、独立应用账号 `forge`（非 root）；Redis 启用密码与 AOF everysec；
两个服务均配置健康检查、`unless-stopped` 与 UTC。

仓库内 `docker/compose.yaml` 与 `.env.example` 作为本机方案保留，本机未安装 Docker，故未在本机运行。

### 本轮修复的真实缺陷

| 缺陷 | 现象 | 处理 |
| --- | --- | --- |
| Jackson 主版本误用 | 沿用 Jackson 2 的 `Jackson2ObjectMapperBuilderCustomizer` 编译失败 | 核对依赖树确认 Boot 4.1 使用 Jackson 3（`tools.jackson`），改为去注解实现并用测试固定 ISO 8601 输出 |
| Flyway 未执行 | 自动配置未生效，数据库只出现业务表、没有迁移历史 | 新增 `FlywayConfig`，显式从动态数据源取 `master` 并在启动时迁移，重复启动验证通过；失败路径由 `FlywayConfigTest` 覆盖 |
| Mapper 扫描未命中 | 启动告警 `No MyBatis mapper was found in 'cn.orangenode.forge.**.mapper'` | 改为 `@MapperScan(basePackages = "cn.orangenode.forge", annotationClass = Mapper.class)`，并新增 `MapperScanningTest`（内存库 + 真实路由数据源）长期守护 |
| 响应体多出字段 | `success` 随 record 访问器输出，违反四字段协议 | 把实例方法改为静态方法 `ApiResponse.isSuccess(int)`，core 保持不依赖 JSON 注解库，并加测试 |
| 分页类型放错模块 | `PageRequest` 放在 core | 按接口设计规范移入 framework 的 Web 入参包，core 只保留框架无关的 `PageResponse` |
| 配置项绑定被静默忽略 | `forge.page.max-size` 改配置与命令行覆盖都无效果，约束因此从未触发；同类的其他字段正常 | 定位为绑定方式问题：setter 绑定与构造器绑定（含 `@DefaultValue`）都读不到该字段，改为字段级 `@Value` 注入后生效，并用 `--forge.page.max-size=5000` 验证启动直接失败；排查方法记入配置管理规范 |

## 6. 下一步：M2 任务

M2 按以下顺序拆解并逐项验证（每项都要断言 HTTP 状态与 body.code）：

1. 公共类型补齐与错误码收敛（`ApiResponse`、`ErrorCode` 与业务异常契约）。
2. 全局异常处理，覆盖 Validation、业务异常、数据库唯一冲突、未知异常。
3. Security 与框架默认错误出口统一写出 HTTP 200 + body.code（未知路径、方法不支持、JSON 解析失败）。
4. Validation 细节：嵌套对象、方法参数、`data.fieldErrors` 结构。
5. 分页：MyBatis-Plus 分页插件、排序白名单、`PageResponse` 映射与空页。
6. 多数据源：第二数据库示例、`@DS` 事务边界、未知数据源名称报错、上下文清理。
7. Redis 封装：Key 前缀、TTL、序列化与故障时不绕过认证的失败语义。
8. OpenAPI 分组（admin/app）、中文说明、字符串 ID 与泛型结构；前端类型生成并锁定工具版本。
9. Checkstyle 接入与注释规则反例验证。

以上为后续实现约定，当前尚未有对应代码，不能据此宣称 M2 已完成。
