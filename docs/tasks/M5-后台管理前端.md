# M5-后台管理前端

状态：已完成（2026-09-30，按用户反馈完成两轮改造）
前置：M4 已完成（文件与存储、审计）。
目标：交付管理员、角色、菜单、权限的管理接口与权限缓存失效，并按用户确认的「克制科技 · Calm Tech」风格实现登录页与全部管理页面，完成响应式与失败分流回归。
必读：[总计划](../项目总计划.md)、[架构](../架构设计.md)、[前端编码规范](../conventions/前端编码规范.md)、[接口设计规范](../conventions/接口设计规范.md)、[数据库设计规范](../conventions/数据库设计规范.md)、[配置管理规范](../conventions/配置管理规范.md)、`frontend/admin/design-showcase.html`（风格基准）、M4 任务。

## 1. 范围与默认值

- 风格基准为用户确认的 `design-showcase.html` 第 01 套「克制科技 · Calm Tech」：浅色底、白色面板、橙色点睛、蓝色主色、圆角与克制阴影。
- 接口前缀仍为 `/api/admin/v1`；所有写操作返回 HTTP 200，前端只按 `body.code` 判定结果。
- 管理接口权限码为 `模块:资源:动作`；超级管理员按配置拥有全部权限，普通角色需显式授予。
- 权限解析改为带版本的缓存：任何角色、权限、管理员角色关系变更后版本递增，所有缓存立即失效；缓存键带版本，旧键按 TTL 自然过期，不使用通配扫描。
- 管理员账号首版只做查询、详情、新增、修改、启停与角色分配，不开放删除；停用与重置密码同时撤销该账号全部令牌。
- 角色、菜单、权限被引用时阻止删除并返回 409，不静默级联。
- 前端以路由白名单渲染菜单，按钮显示按权限控制，但所有接口仍以后端授权为准。
- 窄屏（375px）、平板（768px）、桌面（1440px）三档都要可用：侧边栏可收起、表格在局部容器滚动、表单可操作。

## 3. 实际交付

### 权限、菜单与缓存（T01）

| 位置 | 内容 |

| `db/migration/system/V20260930130000` | 系统管理菜单树（工作台、系统管理目录与四个页面）与 19 个系统权限码；M3 的“概览”菜单前向改名为“工作台” |

| `forge-system/service/impl/AdminAuthorityServiceImpl` | 权限解析带版本化缓存：键 `auth:perm:v{版本}:{管理员ID}`，TTL 来自 `forge.security.permission-cache-ttl-seconds`，版本键 TTL 取权限缓存与令牌有效期的较大值，避免版本键先过期导致旧缓存复活；Redis 连接失败上抛（503），缓存内容损坏按未命中重新解析 |

| `GET`、`POST`、`PUT /{id}`、`DELETE /{id}`（菜单） | `system:menu:view/create/update/delete` |
| `GET`、`POST`、`PUT /{id}`、`DELETE /{id}`（权限） | `system:permission:view/create/update/delete` |

行为约定：用户名统一规范化为小写并校验长度，唯一冲突由数据库唯一键兜底映射为 409；密码按创建规则校验后编码保存并撤销该账号全部令牌；状态变更使用条件更新（受影响行数为 0 返回 409），停用同时撤销令牌；不允许停用当前登录账号；角色被管理员引用、菜单有子节点或被角色引用、权限被角色引用时删除都返回 409；内置超级管理员角色不允许删除或改代码；所有写接口带 `@AuditOperation`，路径参数标注为审计对象。

### 公共包改动

`RequestFactory` 支持应用注入 `tokenProvider`（公共包仍不保存令牌），并把 `query` 类型放宽为对象、只转发字符串/数字/布尔值：调用方通常传带可选字段的接口类型，收窄为 `Record` 会让每个调用点出现无意义的类型错误。

### 缺陷修复

| 缺陷 | 现象 | 处理 |
| --- | --- | --- |
| 分页入参被装配为单例 Bean | 系统管理 Controller 构造器注入 `PageRequest`，容器中没有该 Bean，应用上下文启动失败 | 改为按请求用 `ForgePageProperties` 构造分页入参并在入口校验，避免单例被并发请求互相覆盖 |
| 顶级菜单无法创建 | 提交 `parentId=0` 被“必须是正整数”校验拒绝，真实环境下新建顶级菜单直接 400 | 父菜单解析对约定值 `0` 单独处理，其余取值仍走正整数校验 |
| 审计结果码与响应码不一致 | 唯一键冲突在响应侧是 409，切面只映射业务异常、权限拒绝与依赖不可用，审计因此记成 500 | 切面补充唯一键/完整性冲突 → 409、Redis 与数据源连接失败 → 503，并在注释中说明必须与响应侧同码 |
| 测试夹具权限种子不全 | M5 用例只在内存库种两个权限，超级管理员因此没有 `system:admin:create` 等权限，全部接口返回 403 | 权限种子集中到 `RuntimeSchema.seedPermissions`，与迁移脚本的权限清单一致 |
| 前端字段与后端契约不一致 | 文件列表的上传者名称、存储检测结果字段、默认方案标记与扩展名数组/字符串形态与生成类型不符 | 后端补上传者名称快照（新迁移）；前端按生成类型改用 `available`/`elapsedMillis`/`defaultConfig`，扩展名在表单层与逗号文本互转 |

### 未执行项与限制

- 未在浏览器中检查视觉表现与 375px、768px、1440px 三档响应式；本机没有可用的浏览器环境，`scripts/check-frontend.mjs` 只验证启动、模块加载与代理。Playwright 关键流程用例同样未建立。
- 上传只有加载态，没有百分比进度（请求工厂未暴露 `onUploadProgress`）。
- 权限缓存失效的回滚路径（事务回滚时不失效）没有用例覆盖。
- 逻辑删除后唯一键仍被占用：删除的角色代码、菜单路由标识与权限代码不能复用，重建同名会返回 409，提示未说明原因（与数据库规范“默认不回收唯一业务键”一致，属已知行为）。
- `RuntimeSchema` 的内存库未复刻 MySQL 的大小写不敏感唯一键，用户名、角色代码的大小写重复只能靠应用层规范化覆盖。
