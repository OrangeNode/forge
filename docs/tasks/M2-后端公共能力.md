## 1. 范围与默认值

- 只修改后端 `backend`、前端公共请求包与对应文档；未实现 M3 及以后的业务表、账号与权限逻辑。
- 所有可调参数按[配置管理规范](../conventions/配置管理规范.md)先写入 `application.yaml`，再在代码中读取。
- 应用可处理的响应统一 HTTP 200，成功 `body.code=0`，失败使用 400/401/403/404/405/409/413/415/429/500/503；每项验证同时断言 HTTP 状态与 `body.code`。
- 示例模块继续只承担“装配与验证”职责；新增的验证接口不建业务表、不承载业务流程，随示例模块在 M6 一并移除。
- 第二数据源为可选配置，默认关闭；未配置时不注册，使用该名称会明确报错而不回退主库。
- Redis 只提供键前缀、TTL、序列化与失败语义封装；令牌、限流等身份相关逻辑属于 M3。

### 交付范围调整：排序白名单撤回（2026-09-29 评审后）

初版曾实现 `SortWhitelist`（逻辑字段名 → 数据库列名白名单）、`PageSpec`（分页条件与稳定排序）与 `PageRequest` 的 `sortBy`/`sortDirection` 入参，并在 M2 内验证“非法排序字段返回 400”“指定列排序追加主键稳定排序”。用户评审时指出的问题成立：

- 这三个类在 M2 内**没有任何生产使用者**，被引用的只有测试夹具，属于“为推测中的需求预建抽象”；
- 白名单要管的是“我先开放了任意排序字段”这件事，即需求本身由实现造出来；
- `sortDirection` 的方向规则同时存在于 `@Pattern` 校验与 `resolveAscending` 中，违反“同一规则只有一处来源”。

处理结果：删除 `SortWhitelist`、`PageSpec` 及其测试与 `PageRequest` 的排序字段，只保留 `PageResponses`（对应“不泄漏 `IPage`”这条硬约束）。分页能力仍由分页插件与 `PageResponses` 承担，用法为：`PageRequest` 提供页码条数 → 业务查询构造 MyBatis-Plus `Page` → `PageResponses.from(...)` 转对外结构；排序由具体业务查询的 SQL 决定。相应地撤回两条排序相关的验证结论，并在[接口设计规范](../conventions/接口设计规范.md)记录“排序白名单推迟到第一个真实列表接口时实现”。

前端同步收口：与后端一并撤回的 `sortBy`/`sortDirection` 已从 `PageQuery` 删除（该类型当前没有使用者，等真实列表接口出现时再定义），`request.test.ts` 的“查询参数忽略 undefined 值”用例改用 `pageSize` 作为示例；`src/generated/` 下的生成结果在撤回后按最终代码重新生成。

### 本轮修复与发现的真实缺陷

| 缺陷 | 现象 | 处理 |
| --- | --- | --- |
| `@DS` 注解被静默忽略 | 两个数据源写成同一份数据，路由失效；原因是缺少 AOP 自动配置，注解不生效 | 引入 `spring-boot-starter-aspectj`（Boot 4 中 `spring-boot-starter-aop` 已更名），并用多数据源集成用例长期守护 |
| 分页插件类缺失 | `PaginationInnerInterceptor` 编译失败；MyBatis-Plus 3.5.9 起该类拆分到独立模块 | 父工程与 framework 增加 `mybatis-plus-jsqlparser` 依赖并集中管理版本 |
| 应用启动时 YAML 重复键 | `application.yaml` 出现两个 `forge` 根键，Spring Boot 直接启动失败 | 合并重复段并复核文件，避免“改配置即启动失败”类问题 |
| 错误出口缺少字符集声明 | 容器错误 JSON 未声明 charset，客户端可能按单字节解析中文提示 | `WebErrorWriter` 显式写出 `application/json;charset=UTF-8`，并统一消息转换器默认字符集 |
| 前端字段错误位置不一致 | 前端从顶层读取 `fieldErrors`，后端约定在 `data.fieldErrors`，参数错误明细会丢失 | 前端类型、协议解析与用例同步改为 `data.fieldErrors` |
| 生成脚本被 ESLint 判为未定义全局 | `.mjs` 脚本按浏览器环境检查，`process`/`fetch` 报 `no-undef` | ESLint 平坦配置对 `**/*.mjs` 使用 Node 全局变量 |
| 类型生成脚本在本机无法执行 | `node scripts/generate-api-types.mjs` 报 `spawn EINVAL`：Node 20.12 起在 Windows 上不使用 shell 调用 `.cmd` 会被直接拒绝，原脚本经 `pnpm exec` 调用 `openapi-typescript`，与文档“命令可重复执行”的记录不符 | 脚本改为在进程内调用 `openapi-typescript` 的编程接口（`openapiTS` + `astToString` + `COMMENT_HEADER`），不再创建子进程；生成工具版本仍由 `package.json` 锁定 7.10.1，命令、环境变量与产物路径都不变 |
| 生成的接口类型滞后于撤回后的代码 | `src/generated/admin.ts` 是撤回前生成的快照：含 `sortDirection`、缺少 `status`，与最终 `ValidationSampleController` 不一致；因为都是可选字段，类型检查发现不了 | 用 `standalone` 实例按最终代码重新生成；与旧快照的差异只有 3 处 `sortDirection` → `status` |
