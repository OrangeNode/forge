## 1. 范围与默认值

- 只实现文件与审计；不实现与业务无关的存储管理页面之外的新业务模块。
- 本地存储根目录与临时目录、凭据加密主密钥都来自环境；后台只能配置根目录下的相对目录。
- 存储目标版本化：修改目标（目录、endpoint、bucket）创建新版本；切换默认只影响新上传；被文件引用的配置不可删除。
- 上传硬上限来自 `spring.servlet.multipart.*`；管理员配置的大小限制不得高于硬上限。
- S3 默认私有，下载一律经后端授权；不返回公开桶地址、不返回本地绝对路径与凭据。
- 凭据使用 AES-GCM 加密保存，主密钥来自环境，不复用 nonce，接口与日志都不回显。
- 审计只记录身份快照、动作、对象、结果 code 与 traceId；不记录密码、令牌、请求体与文件内容。
- 登录日志由登录用例写入，包含失败尝试，不因失败而丢失记录。

## 3. 实际交付

### 数据与迁移

| 位置 | 内容 |
| --- | --- |
| `db/migration/file` | `V20260930140000__init_file_tables.sql`：存储配置（`code + version` 版本化、AES-GCM 凭据列、大小与扩展名上限）、默认方案单行指针、文件记录；并种入文件菜单与 10 个权限码。`V20260930160000__add_file_record_uploader_name.sql`：补上传者名称快照列 |
| `db/migration/audit` | `V20260930150000__init_audit_tables.sql`：登录日志与操作日志（只追加、按时间与身份建索引）；并种入审计菜单与 2 个权限码 |

上传者名称按审计表的做法保存快照：文件模块不允许反向依赖账号模块，无法在查询时连接 `sys_admin`，快照同时保证账号改名不影响历史记录。

### 文件模块（forge-file）

| 位置 | 内容 |
| --- | --- |
| `storage` | `ObjectKeyGenerator`（随机值 + UTC 日期分段，不含原文件名）、`LocalStorageProvider`（三层防穿越：相对路径规范化 → 逐段真实路径核对 → `toRealPath` 复核）、`S3StorageProvider`（AWS SDK v2 同步客户端，endpoint + path-style 支持 MinIO；异常只带状态码与错误码，不带 endpoint 与凭据）、`StorageProviderFactory`（按配置版本缓存实例并以目标签名判断复用，变更或删除时关闭客户端） |
| `service` | `FileService`（上传、按 ID 读取元数据与内容流、分页、逻辑删除；上传先写对象再写元数据，元数据失败时补偿删除对象并记录对象键与配置版本）、`FileStorageConfigService`（版本化创建、被引用版本禁止原地修改或删除、默认切换、连接检测）、`StorageConfigResolver`（默认方案解析：指针优先，缺失时回退配置代码的最新有效版本） |
| `controller/admin` | `FileController`（分页、multipart 上传、按 ID 下载、删除）、`StorageConfigController`（列表、默认、创建、修改、删除、检测、切换默认）；写接口带 `@AuditOperation`，路径参数带 `@AuditResourceId` |
| `task` | `FileTempCleanupTask`：按 `forge.file.temp-cleanup-*` 清理临时目录过期文件，只处理第一层普通文件 |

### 审计模块（forge-audit）

| 位置 | 内容 |
| --- | --- |
| `framework/audit`（基础模块） | `@AuditOperation`、`@AuditResourceId`、`AuditOperationRecord`、`AuditRecorder`、`LoginLogRecord`、`LoginLogRecorder`、`AuditOperationAspect`（成功记 0、可预期失败记异常自带 code、权限拒绝记 403、未预期记 500；审计写入失败只记日志，不改变业务结果） |
| `forge-audit` | 两张日志实体与 Mapper、`AuditLogRecorderService`（实现两个端口）、`AuditLogQueryService`（登录日志与操作日志分页，时间范围要求带时区的 ISO 8601，解析失败返回 400）、`AuditLogController`、`AuditLogCleanupTask`（按保留天数清理，受开关控制） |
| 登录日志接入 | `AdminAuthServiceImpl` 在成功、凭据错误、账号停用、触发限流四条路径写入登录日志（`reason` 分别为空、`credentials`、`disabled`、`rate_limited`），身份与追踪编号取自安全上下文与请求 |

### 配置与密钥

- 新增 `forge.file.*`（本地根目录、临时目录、保留小时数、加密主密钥、默认方案代码、清理开关与间隔）与 `forge.audit.*`（登录日志与操作日志保留天数、清理开关与间隔）。
- 凭据加密主密钥只在环境变量中；缺失时保存或读取 S3 凭据明确失败，本地存储不受影响。

### 本轮修复与发现的真实缺陷

| 缺陷 | 现象 | 处理 |
| --- | --- | --- |
| 审计查询未筛选结果码时返回 400 | `GET /audit/operation-logs?pageNum=1&pageSize=5` 返回 400「结果码超出允许范围」：条件构造 `eq(条件, 列, toResultCode(null))` 会先求值再判断条件，`resultCode` 为空时必然抛异常 | 改为仅在结果码非空时构造条件，并在注释中记录原因；真实实例上重新验证通过 |
| 测试脚本编码导致 Checkstyle 失败 | 用 PowerShell 写回的测试文件带 UTF-8 BOM，Checkstyle 报 `no viable alternative at input '?package'` | 去掉 BOM（项目约定 UTF-8 无 BOM） |

### 未执行项与限制

- `DependencyProbeTest` 的 2 个真实中间件探针按设计跳过；本阶段真实依赖验证以启动完整应用并实测接口的方式完成。

- S3 使用 SDK 默认超时；扩展名数量上限、对象键分段布局等未做成配置项。
- 下载接口未加操作审计（读操作不产生审计噪声），如需审计下载需先补验收条目。
