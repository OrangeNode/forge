# Orange Forge 可复用脚手架建设总计划

版本：1.3  
整理日期：2026-09-29  
性质：已确认的建设基线；实施进度以[里程碑与进度](里程碑与进度.md)为准。

1.2 变更：应用可处理的接口响应统一 HTTP 200、只用 body.code 判断结果；M6 由“业务复用示例”改为“示例模块与移除验证”，example 只保留 `GET /hello`，会议业务与会议表退出首版范围。

1.3 变更：前端由“独立管理端 + 独立用户端”收敛为单一后台管理前端；身份由“管理员与普通用户双身份”收敛为单一管理员身份。移除 `frontend/portal`、`forge-member` 模块、`/api/app/v1` 接口前缀、普通用户注册与 OpenAPI app 分组。原因与影响见[架构设计](架构设计.md)第 8 节变更记录。

## 一、目标与命名

建设适合一人配合 AI 持续开发、为不同客户独立交付的脚手架。以后创建客户项目，复用账号、权限、文件、分页、异常处理等公共能力，通过新增业务模块满足需求。

采用 Maven 多模块后端与单个后台管理前端。后端首版作为一个应用运行，前端独立启动、构建和部署，通过后端接口访问。每个客户拥有独立项目、数据库和运行环境。

| 项目 | 约定 |
| --- | --- |
| 项目名称 | `orange-forge` |
| Maven groupId | `cn.orangenode` |
| Java 根包名 | `cn.orangenode.forge` |
| 模块包名示例 | `cn.orangenode.forge.example` |
| 前端私有包命名空间 | `@orange-forge/*` |
| 域名 | `orangenode.cn`，仅作为命名依据与可替换配置示例 |

本次不配置 DNS、证书、反向代理或服务器，不指定主域名、子域名用途。域名不得写死在接口、文件地址和业务代码中；客户项目可以替换项目名、包名与访问地址。

未来五年的适用性通过清晰边界、自动验证和持续升级实现，不承诺固定版本五年不变。

## 二、技术基线

| 类别 | 选型与约定 |
| --- | --- |
| Java | JDK 21，不使用预览特性 |
| 后端 | Spring Boot 4.1 系列、Spring MVC、Spring Security |
| 数据访问 | MyBatis-Plus、HikariCP、dynamic-datasource |
| 参数校验 | Spring Boot Validation，使用 `jakarta.validation` |
| 数据库 | MySQL 8.4 LTS，Flyway 管理结构变更 |
| 主键 | 数据库自增 ID；业务层 Long；对外 ID 为字符串 |
| Redis | Spring Data Redis；登录状态、限流和必要缓存 |
| API 文档 | springdoc-openapi 3.x、OpenAPI、Swagger UI |
| 前端 | Vue 3、TypeScript、Vite、Vue Router、Pinia、Naive UI |
| 文件存储 | 本地文件系统、S3 兼容对象存储 |
| 本地环境 | Docker Compose 启动 MySQL、Redis；应用本机运行 |
| 工程管理 | Maven Wrapper、pnpm 锁文件、统一格式检查与自动测试 |

管理端基于用户指定的 [Naive UI 组件库](https://github.com/tusen-ai/naive-ui)自行搭建轻量后台，不绑定同名管理模板。

M0 核对官方资料并记录候选版本，M1 验证核心组合后锁定精确版本。具体版本、依据及验证状态见[技术选型与版本](技术选型与版本.md)。

首版不引入微服务、注册中心、工作流、消息队列、多租户，也不制作应用 Docker 镜像。不使用 JSP、服务端页面模板、传统 XML Bean 配置。复杂 MyBatis 查询允许使用 Mapper XML。

**常量集中配置**：项目级常量与可调参数先写入 `application.yaml`（前端写入各自 `.env`，通过 `import.meta.env` 读取），再用 `@ConfigurationProperties` 或 `@Value` 读取；禁止在 Java 或 TypeScript 代码里写死端口、数据源名称、分页默认值与上限、追踪响应头名称、超时、路径与日志级别。仅协议不变式留在代码中：HTTP 200、`code`/`message`/`data`/`traceId` 四字段、`body.code` 数值语义。配置项必须有中文注释，可调参数注明默认值与影响；具体规则见[配置管理规范](conventions/配置管理规范.md)。

## 三、项目与模块结构

以下是后续工程目标结构，M0 仅创建文档与 AI 规则入口。

~~~text
orange-forge/
├── backend/
│   ├── pom.xml
│   ├── forge-core/
│   ├── forge-framework/
│   ├── forge-system/
│   ├── forge-file/
│   ├── forge-audit/
│   ├── forge-example/
│   └── forge-application/
├── frontend/
│   ├── admin/
│   └── packages/api-client/
├── docker/
├── scripts/
├── docs/
│   ├── conventions/
│   └── tasks/
└── AGENTS.md
~~~

| 模块 | 职责 |
| --- | --- |
| forge-core | 通用响应、错误码、分页模型及无框架依赖的值类型 |
| forge-framework | Web、安全、数据库、Redis 技术集成 |
| forge-system | 管理员、角色、菜单、权限 |
| forge-file | 文件元数据、存储配置、上传下载 |
| forge-audit | 登录日志、操作审计及查询 |
| forge-example | 可移除的最简示例模块，只提供 `GET /hello` |
| forge-application | 启动入口、环境配置和模块装配 |

依赖约束：

- `core` 不依赖业务，`framework` 依赖 `core`。
- `file`、`audit` 依赖基础模块，不反向依赖账号或示例模块。
- `system` 按需调用文件、审计模块公开服务；`example` 只依赖基础模块。
- `application` 负责装配；禁止循环依赖和跨模块访问 Mapper。
- 安全基础设施定义账号查询接口，由管理员模块实现。
- 业务代码不得进入 `core` 或 `framework`。
- 模块采用构建时装配，不实现运行时插件加载。

### 业务分层

按业务功能组织，再在功能内部划分目录，占位名按实际业务替换：

~~~text
业务模块/
├── controller/
│   └── admin/
├── entity/
├── request/
├── response/
├── service/
│   └── impl/
├── mapper/
├── converter/
├── config/
└── enums/
~~~

按实际需要创建，不生成空目录、空接口或无用途实现。

| 分层 | 职责 |
| --- | --- |
| Controller | 接收参数、触发校验、接口权限声明、调用 Service；后台管理接口放在 `controller/admin` |
| Request | 按新增、修改、查询等用例定义入参 |
| Response | 对外数据结构，不直接返回 Entity |
| Service / Impl | 业务接口、业务规则及事务边界 |
| Entity | 数据库映射 |
| Mapper | 数据访问，复杂查询使用明确 SQL |
| Converter | 显式转换 Entity、Request、Response |
| Config | 模块配置与组件装配 |

### 代码风格

- 使用 `XxxService` 与 `XxxServiceImpl`，构造器注入。
- Lombok 简化访问器和构造器，不使用整类 `@Data`。
- 不把 `IPage`、查询 Wrapper 或 Entity 暴露给前端。
- 所有手写方法和构造器必须有中文多行 Javadoc，包括私有方法、接口声明、实现及测试方法；自动生成的方法除外。
- 重写方法也写明职责；复杂方法补充参数、返回值和业务约束。
- Java 四空格缩进，前端两空格，统一 UTF-8、LF。
- 不创建万能 Controller，不通过反射批量复制业务字段，不捕获异常后返回成功。

~~~java
/**
 * 启用管理员账号。
 */
AdminStatusResponse enable(AdminStatusRequest request);
~~~

## 四、公共能力与接口约定

### 统一接口、分页、校验与异常

- 全部接口使用 `/api/admin/v1/**`，对应唯一的前端后台管理应用。
- JSON 响应为 `ApiResponse<T>`，字段为 `code`、`message`、`data`、`traceId`；成功码为数字 `0`。
- 应用可处理的响应统一使用 HTTP 200；成功 body.code=0，失败在 body.code 中使用 400、401、403、404、409、500 等数值。前端通过 body.code 判断结果，不使用模块六位错误码。
- `PageRequest` 使用 `pageNum/pageSize`，默认 1/20，单页最大 100；非法参数返回校验错误。
- `PageResponse<T>` 使用 `records/total/pageNum/pageSize`；排序字段经过白名单，分页采用稳定排序。
- 所有对外 ID 在 JSON 与 OpenAPI 中表达为字符串，转换时检查正数和 Long 上限。
- Validation 处理字段、嵌套对象和方法参数；业务唯一性由业务检查与数据库约束共同保证。
- 全局异常处理覆盖校验、业务、数据库约束和未知异常；Security 与框架默认错误出口同样返回 HTTP 200 和对应 body.code，且拒绝请求后不继续执行业务。
- 客户端不接收堆栈、SQL、内部连接信息；服务器日志通过 `traceId` 关联。
- 文件下载成功用 HTTP 200 返回二进制流；流开始前的错误用 HTTP 200 返回统一 JSON，前端识别错误体后再决定是否保存文件。网络及代理故障作为传输异常处理。

### 账号与权限

- 首版只有管理员一种身份，使用独立的管理员账号表，不设普通用户表、用户注册与用户端登录入口。
- 管理员由初始化流程或有权限的管理员创建，无公开注册。
- 使用 Spring Security 与 `@PreAuthorize`，权限码为 `模块:资源:动作`。
- 后台管理端具备管理员、角色、菜单和权限管理。
- 前端按权限显示菜单和按钮，后端独立执行权限及资源归属校验。
- 默认随机不透明 Bearer Token，Redis 保存令牌摘要、身份和有效期；默认两小时，可配置，首版无刷新令牌。
- 前端使用自己的 `sessionStorage` 保存令牌；退出、停用、修改密码撤销相关会话。
- 权限变化立即失效相关缓存，不能等登录令牌自然过期。
- 使用 Spring Security 密码编码器；登录加入 Redis 限流；初始管理员密码从环境输入。
- Redis 故障时不绕过认证。

### 文件与存储管理

公开 `FileService` 供业务调用，内部 `StorageProvider` 分别实现本地和 S3 存储。

- 管理员维护存储方案、默认方案、目录前缀、上传大小和允许类型。
- 本地根目录由环境设定，后台只能配置其下相对目录；临时下载目录独立配置并清理过期文件。
- S3 支持 endpoint、region、bucket、凭据和 path-style，使用 AWS SDK for Java 2.x。
- 提供配置校验、连接检测、保存及默认方案切换。
- 凭据加密保存，主密钥来自环境；接口脱敏，日志不记录密钥。
- 元数据保存文件 ID、存储配置版本、对象键、原文件名、大小、类型和上传者。
- 修改存储目标创建新版本；切换只影响新文件，旧文件按原配置读取；有文件引用的配置不可直接删除。
- 历史文件不自动搬迁，迁移另设任务。
- 下载按文件 ID 定位并鉴权；本地防路径穿越，S3 默认私有。
- 上传使用随机对象名，校验大小、扩展名及内容类型；文件失败不记成功，数据库失败执行清理补偿。

### 多数据源、Redis、审计与 API 文档

- dynamic-datasource 主库为 `master`，严格匹配名称，未知名称报错。
- 配置文件添加数据源，Service 使用 `@DS`，提供第二数据库示例。
- Flyway 默认只迁移主库，不自动修改客户外接数据库。
- 数据源切换在事务开始前完成，避免同类自调用绕过代理，不封装跨库原子事务。
- Redis Key 包含项目、环境、模块前缀，缓存明确 TTL 和失效条件。
- 登录日志和操作审计独立于运行日志；提供审计注解，记录身份、动作、对象、结果、追踪编号，不记录密码、令牌或文件内容。
- API 文档使用管理端分组，覆盖中文说明、参数约束、权限和错误响应，生产默认关闭。
- 前端公共包共享请求工具和生成的接口类型，不保存账号状态、页面和布局。

### 数据库统一策略

- 主键采用有符号 `BIGINT AUTO_INCREMENT`，业务层为 Long。
- 账号以停用为主，业务主表默认逻辑删除，关系表物理删除，审计数据按保留策略清理。
- 默认不回收唯一业务键；需要复用时专门设计并发安全的唯一约束。
- 数据库存储 UTC，接口使用带时区的 ISO 8601 字符串，前端按展示时区转换。
- 已发布 Flyway 迁移不可修改，通过新增脚本演进。

## 五、里程碑与验收

按任务依赖推进，不估自然周数。每阶段同步完成文档、验证记录与进度更新。

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| M0 规范与设计 | 命名、架构、编码规范、接口、数据设计、候选版本、AI 规则 | 文档完整且一致，可交接后续实施 |
| M1 工程与环境 | Maven 多模块、前端骨架、Compose、Flyway、检查工具、兼容验证 | 组件健康，后端与前端启动，空库初始化成功 |
| M2 后端公共能力 | 响应、异常、Validation、分页、多数据源、Redis、API 文档 | 基础接口与失败路径通过测试 |
| M3 认证与权限 | 管理员认证、RBAC、权限注解、菜单及登录页 | 管理员正常认证，权限有效，未授权请求被拒绝 |
| M4 文件与审计 | 本地/S3、配置接口、上传下载、日志 | 切换后旧文件可读，越权失败，日志脱敏 |
| M5 后台管理前端 | 管理公共功能页面与登录页 | 管理端闭环，主要页面在电脑与窄屏下可用 |
| M6 示例模块与移除验证 | 最简示例接口、统一响应与失败路径复查、移除装配 | 示例只依赖基础模块；移除示例后仍可构建 |
| M7 模板化交付 | 项目创建脚本、回归、维护文档、版本记录 | 新目录生成独立客户项目并启动，可不包含示例 |

示例模块只提供 `GET /hello`，用于验证模块装配、统一响应与可移除性；不建业务表，也不设计增删改查、附件与权限流程。首版不增加面向普通用户的前台页面或业务页面；后续确需业务示例时先补充需求与任务。

必须验证：

- 身份：错误密码、过期令牌、退出、停用、角色变更、并发登录撤销、越权访问。
- 接口：缺失参数、嵌套校验、非法 ID、空分页、分页超限、非法排序、异常响应一致性。
- 数据：真实 MySQL 的主库、第二库、未知名称、单库回滚、数据源上下文清理。
- 文件：本地/S3 上传下载、中文文件名、超限、路径穿越、历史文件读取、失败补偿。
- 前端：登录、菜单按钮权限、HTTP 200 下 body.code=401/403/500/503 的异常分流、重复提交、375px/768px/1440px 布局。
- 交付：空库安装、数据库升级、Compose 重启持久化、移除示例、创建客户项目及重新构建。
- 命名：替换包名后能编译，更换访问地址无需改业务代码。

检查工具采用 Checkstyle、ArchUnit、后端单元与集成测试、ESLint、类型检查、Vitest、关键流程 Playwright。S3 需要真实兼容服务验收，不能用模拟测试代替厂商兼容验证。

## 六、文档与 AI 开发

普通文档文件名使用中文，阶段编号保留。当前只建立 `docs/conventions` 和 `docs/tasks` 两个子目录。

- 总计划管理整体目标、范围和里程碑。
- 需求、架构、技术选型分别维护相应事实与设计。
- 编码与接口规范集中在 `conventions`。
- 任务文档管理执行状态、验收和下一步。
- AI 规则集中在根目录 `AGENTS.md`，正文中文；任务模板放在阶段任务文档。
- 设计决策集中写入架构文档，不创建单独决策目录。
- 操作指南待功能实现并验证后按需添加，不预建指南目录。

AI 每次先读规则与当前任务，按单个可验证任务实施，不顺带改无关模块；变更后运行相关检查并同步文档，不将未执行验证标记为通过。

## 七、交付与维护

客户项目生成脚本接收项目名、Maven groupId、Java 包名前缀及是否包含示例；只写入不存在的目标目录，不复制凭据、缓存和构建产物。

首版不增加后台动态数据源管理、短信、社交登录、多租户或服务器部署任务。后续新需求先补任务与验收，再实现。

每月检查依赖和安全更新，每季度集中验证升级；重大升级写迁移说明。脚手架按版本发布，客户项目记录来源基线，根据变更说明迁移，不直接覆盖客户业务代码。

本机环境及尚未验证事项记录在[技术选型与版本](技术选型与版本.md)。本计划描述目标，不代表应用已经实现或运行。
