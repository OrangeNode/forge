# 服务器部署教程

按步骤把后端与后台管理端部署到一台 Linux 服务器，以及之后如何更新、回滚、备份。部署结构、入口划分、安全措施与历次部署记录见《[部署指南](部署指南.md)》；域名配置见《[域名与 nginx 配置教程](域名与nginx配置教程.md)》；日常命令速查见《[常用命令](常用命令.md)》。

标注：“已验证”表示在测试服务器或本机实际执行过；“未实际执行”表示按官方文档整理，现有服务器没有用到（例如服务器出厂已装好 Docker）。

下面第 1—5 节是从零部署一台新服务器的完整过程；现有服务器日常更新只看第 6 节。

## 1. 准备

**服务器**：Ubuntu 22.04/24.04，x86_64，至少 2 核 2 GiB 内存（建议 4 GiB），20 GiB 以上磁盘；能用 root 或 sudo 登录。

**本机（Windows）**：JDK 21、Node 与 pnpm、Docker Desktop（只在需要离线导入镜像时用）、OpenSSH 客户端（Windows 自带 `ssh`、`scp`）。

**云厂商安全组**：放行 SSH 端口、80，以及后台、App 两个高位端口（如果保留）。安全组在云厂商控制台设置，服务器里的防火墙管不到它。

## 2. 服务器初始化

### 2.1 用密钥登录

本机生成部署钥匙（已有 `orange_deploy_ed25519` 可跳过）：

~~~powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\orange_deploy_ed25519 -C orange-deploy
type $env:USERPROFILE\.ssh\orange_deploy_ed25519.pub   # 复制这一行
~~~

用服务商给的口令登录服务器，把公钥写入：

~~~bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo '<粘贴上面那一行公钥>' >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
~~~

本机测试：`ssh -i $env:USERPROFILE\.ssh\orange_deploy_ed25519 root@<服务器IP>`。确认能用钥匙登录后，再按《部署指南》第 6 节改 SSH 端口、关闭口令登录、装 fail2ban（**先在新窗口确认新端口能登录，再关旧端口**，否则会把自己锁在外面）。

### 2.2 安装 Docker（未实际执行，测试服务器已预装）

按 Docker 官方 apt 源安装 Docker Engine 与 Compose 插件：

~~~bash
apt-get update && apt-get install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" > /etc/apt/sources.list.d/docker.list
apt-get update && apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
docker version && docker compose version
~~~

### 2.3 防火墙

~~~bash
ufw allow <SSH端口>/tcp
ufw allow 80/tcp
ufw allow <ADMIN_PORT>/tcp     # 保留高位端口入口时
ufw allow <APP_PORT>/tcp
ufw enable
~~~

注意：Docker 发布的端口不受 ufw 控制，真正关闭某个入口要改 `.env` 的端口绑定（见《部署指南》第 1 节）。

## 3. 本机构建

在仓库根目录 `E:\project\orange-forge` 执行（已验证）：

~~~powershell
cd E:\project\orange-forge
# 后端 jar；正式发布前建议先跑一次完整检查：cd backend; .\mvnw.cmd -B clean verify
cd backend; .\mvnw.cmd -B package -DskipTests; cd ..
# 后台管理端页面
cd frontend; pnpm install; cd admin; pnpm run build; cd ..\..
~~~

产物：

- `backend\forge-application\target\forge-application-1.0.0.jar`
- `frontend\admin\dist\`

Maven 报 `Unable to establish loopback connection` 时先执行 `$env:TMP='E:\dev\tmp'; $env:TEMP='E:\dev\tmp'`。

## 4. 上传

服务器上建目录：

~~~bash
mkdir -p /opt/orange-forge/backend /opt/orange-forge/web
~~~

本机上传部署文件与两个产物（已验证）：

~~~powershell
cd E:\project\orange-forge
$key = "$env:USERPROFILE\.ssh\orange_deploy_ed25519"
$srv = 'root@103.242.13.62'
scp -i $key -P 42722 deploy\compose.yaml deploy\.env.example "${srv}:/opt/orange-forge/"
scp -i $key -P 42722 deploy\backend\Dockerfile "${srv}:/opt/orange-forge/backend/"
scp -i $key -P 42722 -r deploy\web\Dockerfile deploy\web\nginx.conf deploy\web\snippets "${srv}:/opt/orange-forge/web/"
scp -i $key -P 42722 backend\forge-application\target\forge-application-1.0.0.jar "${srv}:/opt/orange-forge/backend/app.jar"
scp -i $key -P 42722 -r frontend\admin\dist "${srv}:/opt/orange-forge/web/"
~~~

上传后服务器目录应为：

~~~text
/opt/orange-forge/
├── compose.yaml
├── .env.example
├── .env              ← 下一步生成，只在服务器
├── backend/  Dockerfile、app.jar
└── web/      Dockerfile、nginx.conf、snippets/、dist/
~~~

**基础镜像**：测试服务器访问不了 Docker Hub，四个基础镜像需要在本机拉取后上传导入，命令见《常用命令》第 5.3 节。能访问 Docker Hub 的服务器跳过这一步。

## 5. 配置并启动

### 5.1 生成 .env

~~~bash
cd /opt/orange-forge
cp .env.example .env && chmod 600 .env
openssl rand -hex 24      # 执行三次，分别填 MYSQL_ROOT_PASSWORD、MYSQL_PASSWORD、REDIS_PASSWORD
openssl rand -base64 32   # 填 FORGE_FILE_ENCRYPTION_KEY
openssl rand -base64 12   # 填 FORGE_INIT_ADMIN_PASSWORD（初始管理员口令）
nano .env
~~~

必须填写的项：

| 变量 | 说明 |
| --- | --- |
| `ADMIN_PORT`、`APP_PORT` | 后台、App 高位端口，选未被占用的端口 |
| `ADMIN_HOST`、`API_HOST` | 后台域名与 App 接口域名，例如 `admin.orangenode.cn`、`api.orangenode.cn` |
| `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`REDIS_PASSWORD` | 随机口令 |
| `FORGE_FILE_ENCRYPTION_KEY` | 存储凭据加密主密钥，**设置后不要再改**，否则已保存的存储凭据无法解密 |
| `FORGE_INIT_ADMIN_PASSWORD` | 初始管理员 `admin` 的口令 |

`.env` 只在服务器保存，不复制回本机、不发到聊天里。建议另外离线备份一份（加密保存），服务器重装时需要它才能读回存储凭据。

### 5.2 启动

~~~bash
cd /opt/orange-forge
docker compose up -d --build --wait     # 已验证：四个容器 healthy 后返回
docker compose ps
docker compose logs --tail 100 backend  # 看到 Started ... 即启动成功
~~~

首次启动时 Flyway 自动建表、写菜单与权限，并创建初始管理员。

### 5.3 验证

~~~bash
# 在服务器上（用域名入口；Host 头模拟域名访问）
curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: admin.orangenode.cn' http://127.0.0.1/   # 200
curl -s -H 'Host: api.orangenode.cn' http://127.0.0.1/api/app/v1/app/launch | head -c 200      # "code":0
~~~

浏览器打开后台域名，用 `admin` 与 `.env` 里的初始口令登录（需要填图形验证码），**登录后立刻在“系统管理 → 用户管理”对 admin 点“重置密码”换成自己的口令**（后台没有单独的“修改我的密码”入口）。之后按《[后台使用教程](后台使用教程.md)》第 2 节做首次配置。

## 6. 更新版本（日常）

每次后端或后台有改动时执行。数据在命名卷里，更新不影响数据。

1. 本机按第 3 节重新构建。
2. 服务器上先留一份旧包，方便回滚：

~~~bash
cd /opt/orange-forge
cp backend/app.jar backend/app.jar.prev
rm -rf web/dist.prev && cp -r web/dist web/dist.prev
~~~

3. 本机上传新包并重建（已验证）：

~~~powershell
cd E:\project\orange-forge
$key = "$env:USERPROFILE\.ssh\orange_deploy_ed25519"
scp -i $key -P 42722 backend\forge-application\target\forge-application-1.0.0.jar root@103.242.13.62:/opt/orange-forge/backend/app.jar
ssh -i $key -p 42722 root@103.242.13.62 "rm -rf /opt/orange-forge/web/dist"
scp -i $key -P 42722 -r frontend\admin\dist root@103.242.13.62:/opt/orange-forge/web/
ssh -i $key -p 42722 root@103.242.13.62 "cd /opt/orange-forge && docker compose up -d --build --wait backend web && docker compose ps"
~~~

只改了后端就只传 jar，只改了页面就只传 `dist`。改了 `deploy\` 下的 `compose.yaml`、`web\nginx.conf`、`web\snippets\` 或 Dockerfile 时，把对应文件一起上传到服务器同名位置。

4. 检查：`docker compose logs --tail 100 backend` 没有报错，后台能登录，App 能打开。数据库迁移（Flyway）在后端启动时自动执行，日志里能看到执行了哪些版本。

## 7. 回滚

新版本有问题时换回第 6 节保留的旧包（未实际执行）：

~~~bash
cd /opt/orange-forge
cp backend/app.jar.prev backend/app.jar
rm -rf web/dist && cp -r web/dist.prev web/dist
docker compose up -d --build --wait backend web
~~~

注意：如果新版本带了数据库迁移，旧后端可能无法使用新表结构（Flyway 发现数据库版本比代码新会拒绝启动）。这种情况不要删数据硬回滚，应修好问题后发一个更新的版本。所以带迁移的版本上线前，先按第 8 节备份数据库。

## 8. 备份与恢复（未实际执行）

数据都在三个命名卷：`orange-forge_mysql-data`（数据库）、`orange-forge_redis-data`（登录会话等，可丢）、`orange-forge_forge-files`（上传的图片与安装包）。

备份数据库与上传文件：

~~~bash
cd /opt/orange-forge
mkdir -p /root/backup
# 数据库（在线备份，不停服务）
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction --routines --triggers "$MYSQL_DATABASE"' \
  | gzip > /root/backup/db-$(date +%F).sql.gz
# 上传文件
docker compose exec -T backend tar czf - -C /data forge-files > /root/backup/files-$(date +%F).tar.gz
ls -lh /root/backup
~~~

再把备份下载到本机保存：

~~~powershell
scp -i $env:USERPROFILE\.ssh\orange_deploy_ed25519 -P 42722 "root@103.242.13.62:/root/backup/*" E:\dev\backup\
~~~

恢复数据库（会覆盖现有数据，确认后再执行）：

~~~bash
cd /opt/orange-forge
gunzip -c /root/backup/db-<日期>.sql.gz \
  | docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot "$MYSQL_DATABASE"'
docker compose restart backend
~~~

恢复上传文件：

~~~bash
docker compose exec -T backend tar xzf - -C /data < /root/backup/files-<日期>.tar.gz
~~~

## 9. 日常运维

~~~bash
cd /opt/orange-forge
docker compose ps                         # 状态
docker compose logs -f backend            # 后端日志（Ctrl+C 退出）
docker compose logs --tail 200 web        # nginx 访问与错误日志
docker compose restart backend            # 重启后端
docker compose stop / docker compose up -d   # 全部停止 / 启动，数据保留
df -h && docker system df                 # 磁盘占用
grep FORGE_INIT_ADMIN_PASSWORD .env       # 查看初始管理员口令
~~~

**绝对不要执行 `docker compose down -v`**：`-v` 会删除数据库、Redis 与上传文件三个数据卷。

## 10. 常见问题

| 现象 | 处理 |
| --- | --- |
| `docker compose up` 报“请在 .env 中设置 XXX” | `.env` 缺少该项，按第 5.1 节补上 |
| 拉取镜像超时 | 服务器访问不了 Docker Hub，按《常用命令》5.3 离线导入 |
| backend 一直重启 | `docker compose logs backend` 看原因；常见是数据库口令与 MySQL 数据卷初始化时不一致（MySQL 口令只在第一次建卷时生效，之后改 `.env` 要在库内 `ALTER USER`） |
| 改了 `FORGE_INIT_ADMIN_PASSWORD` 但登录还是旧口令 | 初始管理员只在账号表为空时创建一次。忘记口令时让其他管理员在“系统管理 → 用户管理”重置 |
| 后台登录提示锁定 | 同一账号连续输错 5 次锁定 15 分钟，等待后再试 |
| 后台打不开但 IP 加高位端口能打开 | 域名解析或 `ADMIN_HOST` 配置问题，见《域名与 nginx 配置教程》 |
| 上传安装包提示过大 | 请求体上限 210 MB，在 `deploy/web/snippets/admin-site.conf` 的 `client_max_body_size` |
| 采集一直失败 | 后台“视频管理 → 采集记录”看失败原因；资源站地址失效时在“资源站管理”更换 |
