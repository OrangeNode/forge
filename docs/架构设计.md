# 架构设计

本文件定义 M0 架构基线及关键设计决策。整体范围见[项目总计划](项目总计划.md)，数据与接口分别以对应规范为准。

## 1. 运行结构

同一仓库管理一个 Vue 后台管理应用和一个 Maven 多模块后端。前端独立维护页面、路由、身份状态和环境配置。Java 后端作为一个应用运行，各客户使用独立实例与数据库。

~~~text
后台管理前端 admin ── /api/admin/v1 ── forge-application ── MySQL
                                                  │
                                                  ├─ Redis
                                                  └─ 本地目录 / S3
~~~

应用本机运行，MySQL 与 Redis 由 Compose 提供。运行地址由配置确定，本阶段不绑定服务器域名或部署拓扑。

## 2. 模块依赖

箭头表示“调用方依赖被调用方”：

~~~text
application → system / file / audit / example / framework
system      → framework / core / file / audit（按实际使用）
example     → framework / core
file        → framework / core
audit       → framework / core
framework   → core
core        → JDK
~~~

公共接口可以位于现有模块的 `api` 包，首版不为每个业务再拆一套 api/impl Maven 子模块。公开接口使用本模块对外契约，不能把内部 Entity、Mapper 或实现类作为调用入口。

| 模块 | 拥有的能力 | 不应承担 |
| --- | --- | --- |
| core | ApiResponse、分页结果、错误码契约等无框架依赖的值类型 | Spring、数据库实现、具体账号查询 |
| framework | Web/Validation 适配、安全过滤链、Redis、持久化配置 | 业务规则、管理员表 Mapper |
| system | 管理员、角色、菜单与权限 RBAC | 文件与审计的持久化实现 |
| file | 配置版本、文件元数据、存储适配 | 查询其他模块业务表推断权限 |
| audit | 审计持久化与查询 | 反向查询账号模块生成运行依赖 |
| example | 最简示例接口 `GET /hello` | 基础模块依赖它才能启动 |
| application | 装配、全局运行配置 | Controller 或业务 Service |

默认不在兄弟业务模块之间增加依赖。需要跨模块协作时使用已有公开契约；跨模块流程放在调用方业务服务中。

### 避免安全与审计循环依赖

- `framework` 定义 `AdminAccountDirectory` 等技术端口，按管理员身份查询认证所需信息（账号视图与权限代码）。
- `system` 提供实现（`AdminAccountDirectoryImpl`），Spring 在启动时装配。过滤链只接受管理员身份，不提供替代身份入口。
- `framework` 提供审计注解、审计记录端口和基础身份上下文；`audit` 实现审计保存与查询。
- 文件模块可使用基础审计注解，无需反向依赖审计业务实现；审计模块保存操作者身份快照，不查询账号模块。
- 身份上下文只保存一次请求必要的数据，结束后清理，不能跨请求复用。

## 3. 请求与数据流程

### 后台管理请求

1. 前端请求工具添加 Bearer Token。
2. Security 按管理路径验证管理员身份、令牌有效期和账号状态。
3. Controller 接收 Request，触发 Validation，声明所需权限。
4. Service 完成业务授权、规则、事务与必要的文件或审计调用。
5. Mapper 访问当前业务拥有的表，Converter 输出 Response。
6. Web 层统一返回 HTTP 200，成功 body.code=0；异常经全局处理写入非零 code，Security 和框架默认错误出口走同一错误写出组件。前端收到 HTTP 200 后仍检查 body.code。

业务层使用 Long ID；HTTP 层接收和返回字符串 ID，并校验格式、正数、Long 范围。前端不将 ID 转为 Number。

当前管理员接口从认证上下文取账号 ID，不接受客户端指定“当前账号 ID”。仅显式列出的登录等入口匿名可访问。

### 授权与缓存一致性

Token 是不可预测的随机值，服务器保存摘要，浏览器保存在后台管理前端的 `sessionStorage`。默认有效期两小时，首版不自动续期。

会话关联管理员账号 ID 与令牌摘要。退出撤销当前令牌；停用、密码变更撤销该账号的相关令牌。采用账号会话索引或版本失效机制时必须验证并发登录不会留下可用的旧会话；具体 Redis 原子操作在 M3 任务中落实。

权限更新以数据库为事实来源，提交成功后失效权限缓存；不能把权限永久固化在会话里直到自然过期。Redis 不可用时拒绝受保护请求，返回 HTTP 200、body.code=503，不继续执行业务。

M3 实际实现（`framework` 的 `AdminTokenService`、`LoginAttemptGuard`、`BearerTokenAuthenticationFilter`，`system` 的权限解析）：

- **令牌与会话**：令牌为 32 字节安全随机值，Redis 键名为其 SHA-256 摘要，值为账号 ID、签发时的会话版本与签发时刻；键带令牌有效期。日志与响应都不出现令牌明文。
- **撤销采用会话版本**：退出只删除当前令牌键；停用、改密等按账号递增 `auth:session-version:<管理员ID>`，签发时记录版本、校验时比对，因此撤销前签发的所有令牌在下一次请求即失效，并发登录也不会留下可用旧会话。版本键的存活时间不小于令牌有效期，不会出现“版本键先过期、旧令牌复活”。
- **权限缓存与失效（M5 更新，2026-09-30 调整）**：M3 阶段权限按请求实时查询数据库；M5 引入管理接口后改为带全局版本的缓存——缓存键为 `auth:perm:v{版本}:{管理员ID}`，TTL 来自 `forge.security.permission-cache-ttl-seconds`；任何角色、菜单权限标识、管理员角色关系变更在事务提交后递增版本，全部既有缓存立即失效，旧键按 TTL 自然过期，不使用通配扫描。角色代码与超级管理员判断仍每次查询数据库：数据量极小，且会话撤销与停用依赖实时结果。缓存读取遇到 Redis 连接失败时上抛 503，缓存内容损坏按未命中重新解析。
- **RBAC 载体为菜单节点（2026-09-30）**：管理员、角色、菜单三类主数据构成 RBAC。角色只授予菜单节点（`sys_role_menu`），菜单节点直接保存权限项的代码、中文名称和说明（`sys_menu.permissions_json`），并以 `perm_codes` 作为鉴权查询索引。权限是该角色可见菜单节点所声明代码的并集，因此不存在独立的权限主表与角色权限关系表：角色与菜单的授权关系、菜单节点的权限声明合起来就完整表达了“谁能调用什么接口”。权限代码在全局唯一，被两个节点声明会被拒绝，避免权限来源不可解释；授权时一次勾选同时得到菜单可见性与节点权限。
- **菜单元数据（2026-09-30）**：菜单保存目录/页面类型与图标标识；目录不要求前端路由，页面路由仍必须进入本地白名单。权限的中文资料随菜单一同增改，不再依赖 `sys_permission`，该表由后续迁移删除。
- **依赖故障**：令牌校验、限流与权限缓存都依赖 Redis；Redis 不可用时过滤链直接写出 503 并终止请求，不降级为匿名，也不继续执行业务。
- **超级管理员**：按 `forge.security.super-role-code` 识别的角色在解析时拥有全部有效权限与全部有效菜单，使空库安装后的初始管理员能够管理工作台自身；该判断只用于解析，不改变“权限以数据库为事实来源”。

## 4. 数据边界

每个模块拥有自己的表和迁移。其他模块通过公开服务取得必要数据，不直接注入 Mapper 或跨模块写表。

默认只使用主库 `master`。第二数据源作为独立数据库示例，配置后启用。数据源名称来自可信配置与后端代码，不接受请求参数直接选择连接。

`@DS` 在事务开始前选库；同类自调用不经过代理，不能用这种方式切换数据源或启动事务。一个业务事务默认只对单个数据库提供原子性。

Flyway 显式针对主库运行，并只加载装配模块的迁移目录。客户外接库不自动初始化或迁移。

## 5. 文件存储边界

`FileService` 负责文件元数据、调用者授权与失败处理；`StorageProvider` 只负责对象读写及连接能力，不决定业务权限。

文件记录引用存储配置版本，配置目标版本不可原地修改为另一个目录或桶。默认存储选择只影响新上传：

1. 获取并固定本次使用的配置版本。
2. 校验路径、类型和大小，生成随机对象键。
3. 调用本地或 S3 写入。
4. 保存文件元数据，返回稳定文件 ID。
5. 数据库保存失败时尝试删除刚写入对象；补偿失败记录可追踪清理事项，不能报上传成功。

下载先依据文件 ID 和权限定位记录，再用记录引用的配置读取。通用下载允许上传者或具备相应管理权限者；业务需要共享附件时，由该业务 Service 先检查资源权限，再调用内部文件读取服务。

本地根目录与临时目录来自环境，后台相对路径必须规范化并验证仍位于根目录内，考虑符号链接或 Windows junction。S3 默认私有，通过后端授权读取；首版不默认返回公开桶地址。

凭据加密保存，加密主密钥仅在环境中。存储目标配置保留历史版本，凭据轮换不得通过删除历史目标破坏旧文件读取。

M4 实现落点（`forge-file` 与 `forge-audit`，端口与切面在 `forge-framework`）：`StorageProvider` 由本地与 S3 两个适配实现，按配置版本创建并由工厂缓存（变更时关闭客户端）；本地适配做三层路径防穿越（相对路径规范化、逐段真实路径核对、`toRealPath` 复核），对象键只由随机值与 UTC 日期组成；上传先写对象再写元数据，元数据失败时补偿删除对象并留下可追踪日志，不报告成功；下载按文件 ID 鉴权后流式返回，失败发生在流开始前时仍是统一 JSON。审计由 `@AuditOperation` 注解与切面完成，结果码与响应侧保持一致，审计写入失败只记日志、不改变业务结果，实现落在 audit 模块，基础模块不反向依赖业务。

### 配置归属与生效方式

| 配置 | 来源与边界 | 生效方式 |
| --- | --- | --- |
| 主库、Redis、多数据源连接 | 环境变量覆盖环境配置文件；凭据不提交 | 重启应用 |
| 本地根目录、临时目录、加密主密钥 | 部署环境；生产缺失关键值应明确失败 | 重启应用 |
| 本地相对目录、S3 目标、上传策略 | 管理员保存的数据库配置版本 | 校验通过后，新请求使用 |
| 默认存储版本 | 数据库唯一默认指针 | 切换提交后影响新上传 |
| 上传硬上限 | 应用环境配置 | 重启应用 |
| 管理员上传大小限制 | 不能高于环境硬上限 | 新上传使用 |
| API 基础地址 | 后台管理前端环境配置 | 构建或开发服务器配置 |
| CORS 来源、对外地址 | 后端环境配置，精确列出允许来源 | 重启应用 |

同一文件上传事务不因管理员中途切换默认方案而改变目标。已失效的缓存不应恢复旧的默认选择。

## 6. 前端与接口类型

`frontend/admin` 是唯一前端应用。`frontend/packages/api-client` 保留为独立工作区包，承载请求工厂、公共协议类型与按管理端 OpenAPI 分组生成的接口类型，不保存令牌、路由实例或账号 Store；当前只有后台管理前端一个使用方，若长期只有单一使用方且没有可复用价值，再评估并入应用目录。

管理端建立本地路由与页面白名单，后端菜单引用其中的路由标识；不执行服务器传回的组件代码或任意导入路径。按钮隐藏只改善体验，后端授权仍是最终依据。

M5 实现落点：管理端为单一 Vue 应用，按用户确认的「克制科技 · Calm Tech」风格实现布局与页面（工作台、系统管理、文件与存储、审计中心）；主题令牌集中在 `src/theme/calm-tech.ts`，路由白名单在 `src/router/menu-routes.ts`，菜单只渲染白名单内的标识；令牌保存在 `sessionStorage`，受保护请求由请求工厂注入，401 清理会话并跳转登录页，登录失败不跳转；文件下载按 ID 调用 `src/utils/download.ts`，先识别 HTTP 200 的 JSON 错误体再决定是否保存文件。

2026-09-30 布局与导航调整：整屏固定布局（侧边栏与顶栏不随页面滚动，菜单区与内容区各自内部滚动），侧边栏可折叠为图标轨道，顶栏下方为多标签条（最多保留最近 12 个标签，右键关闭当前/其他/左侧/右侧/全部），页面统一用 `src/components/PageBody.vue` 承担内边距与内部滚动；菜单与权限合并在「菜单与权限」页面维护。

API 地址统一来自配置。原始文件路径不进入页面数据结构；使用文件 ID 调用授权接口。

## 7. 新增与移除业务模块

新增步骤：

1. 在 backend 下建立业务模块，根包沿用 `cn.orangenode.forge`。
2. 注册父工程模块和 application 的业务依赖。
3. 按功能分层，定义 Request/Response、接口权限与业务规则。
4. 新增所属模块迁移目录及权限种子，分配全局唯一迁移版本。
5. 接入管理端页面和静态路由标识，用权限数据生成可见菜单。
6. 复用分页、异常、文件、审计；补业务关键成功和失败用例。

移除示例模块时，移除父工程与 application 装配、前端页面和路由入口，以及全新模板中的示例相关配置。不得删除已部署客户库的迁移历史来“卸载模块”；已有安装的权限下线和数据处理另用前向迁移完成。

基础模块不得引用示例模块的类。M6/M7 同时验证带示例与不带示例的新项目。

## 8. 设计决策

| 决策 | 采用原因 | 重新评估的触发条件 |
| --- | --- | --- |
| 模块化单体 | 独立客户项目交付简单，适合个人维护 | 明确出现独立扩容或独立发布需求 |
| 单一后台管理前端与单一管理员身份 | 用户明确前端只保留一个后台管理应用；管理员一种身份边界清楚，不需要维护两套账号、会话与接口前缀 | 客户需要面向终端用户的前台时，先补身份与端拆分需求与任务 |
| HTTP 200、body.code 判定结果 | 按用户风格统一前后端错误分流；成功 0，异常使用 401、403、500 等 | 用户明确调整公共响应协议 |
| 构建时模块装配 | 依赖可检查，删除模块可验证 | 明确需要运行时安装模块 |
| 自增 ID、接口字符串 | 独立库易维护，前端避免整数精度丢失 | 明确要求离线生成或跨库全局 ID |
| 按类型删除 | 保留业务主记录，同时避免关系表历史复杂化 | 具体业务出现恢复或法定留存要求 |
| 权限标识挂在菜单节点上（2026-09-30） | 用户明确 RBAC 只需要用户、角色、菜单三张表：权限标识在菜单上配置，权限维护与菜单维护同一入口；角色授权只勾菜单，权限由节点声明推导，少一张主表与一张关系表 | 出现“同一接口权限需要授予多个互不相关页面”或权限需要独立生命周期时，重新评估权限是否回归独立主数据 |
| 配置式多数据源 | 减少运行时连接管理与密钥维护复杂度 | 确有后台动态接入外部数据库需求 |
| 文件配置版本化 | 新旧文件使用各自实际存储位置 | 增加显式迁移、归档任务 |
| 文档目录精简 | 个人与 AI 可快速找到规则 | 文档规模已影响查找和维护 |

当前决定不引入独立 ADR 目录。决策变化先更新本节和相关规范，再同步受影响任务。
