# 部署指南

本文件记录测试服务器的 Docker 部署方式。2026-10-08 起，用户要求把后端与管理端部署到测试服务器，供 App 真机测试；此前“不做服务器部署、不制作应用镜像”的范围因此调整（见[需求与范围](需求与范围.md)）。正式环境的域名、证书与 HTTPS 尚未纳入。

## 1. 组成

部署文件在仓库 `deploy/` 目录，一个 Compose 项目包含四个服务：

| 服务 | 镜像 | 对外 | 说明 |
| --- | --- | --- | --- |
| mysql | `mysql:8.4.11` | 否 | 命名卷 `mysql-data` 持久化 |
| redis | `redis:8.10.1-alpine` | 否 | 口令认证、AOF 持久化，命名卷 `redis-data` |
| backend | `eclipse-temurin:21.0.8_9-jre-noble` + 本地构建的 jar | 否 | 不启用开发 profile（接口文档关闭）；上传文件在命名卷 `forge-files` |
| web | `nginx:1.28.0-alpine` + 管理端 `dist` | 是（`HTTP_PORT`，默认 80） | 托管管理端页面，`/api/` 反向代理到后端 |

App 与管理端共用 web 的一个对外端口：管理端 `http://<服务器>:<端口>/`，App 接口地址 `http://<服务器>:<端口>`。MySQL、Redis 与后端只在 Compose 内网中可达。

后端位于 nginx 之后，`FORGE_FORWARD_HEADERS_STRATEGY=native`（`application.yaml` 中 `server.forward-headers-strategy`）让 Tomcat 从内网代理传入的 `X-Forwarded-For` 还原客户端地址；nginx 覆盖写入该请求头，客户端无法伪造。限流与登录日志因此按真实来源计算。

## 2. 构建（本机，仓库根目录）

~~~powershell
# 后端 jar（测试已在本机 clean verify 通过时可跳过测试）
cd backend; .\mvnw.cmd -B package -DskipTests; cd ..
# 管理端 dist
cd frontend\admin; pnpm run build; cd ..\..
# 复制到 deploy/（两者均被 .gitignore 忽略）
Copy-Item backend\forge-application\target\forge-application-1.0.0.jar deploy\backend\app.jar -Force
Remove-Item -Recurse -Force deploy\web\dist -ErrorAction SilentlyContinue
Copy-Item -Recurse frontend\admin\dist deploy\web\dist
~~~

## 3. 上传与启动（服务器）

服务器需要 Docker Engine 与 Compose 插件。项目目录 `/opt/orange-forge`，上传 `deploy/` 下的全部内容（`compose.yaml`、`.env.example`、`backend/`、`web/`）。

首次部署在服务器生成 `.env`（只在服务器保存，`chmod 600`）：

~~~bash
cd /opt/orange-forge
cp .env.example .env && chmod 600 .env
# 每项口令用随机值，例如：
openssl rand -hex 24          # MYSQL_ROOT_PASSWORD、MYSQL_PASSWORD、REDIS_PASSWORD
openssl rand -base64 32       # FORGE_FILE_ENCRYPTION_KEY
openssl rand -base64 12       # FORGE_INIT_ADMIN_PASSWORD
# 服务器无法访问 Docker Hub 时：在本机 docker pull 后 docker save | gzip 上传，服务器 gunzip -c ... | docker load
docker compose up -d --build --wait
docker compose ps
docker compose logs -f backend
~~~

更新版本：重新执行第 2 节构建，只上传 `backend/app.jar` 或 `web/dist`，再 `docker compose up -d --build backend web`。数据卷不受影响；不要用 `docker compose down -v`。

注意：

- MySQL 初始化变量只在空数据卷时生效；之后修改 `.env` 中数据库口令需要在库内 `ALTER USER`。
- 初始管理员只在管理员账号表为空时创建，之后修改 `.env` 中的初始口令不会改变已有账号。
- 普通用户用用户名 + 密码注册登录（2026-10-08 起），不需要配置发信服务；服务器 `.env` 中旧的 `FORGE_MAIL_*` 行不再被读取，可以删除。
- 防火墙只放行 `HTTP_PORT`；云厂商安全组需要在控制台另行放行。

## 4. App 发布新版本

1. 在 orange-app 提高 `pubspec.yaml` 的版本号（`1.0.2+3` 中 `+` 后的数字必须比当前已发布的大），用正式签名打包（见 orange-app README）。
2. 后台“App 管理 → 版本更新”选择 APK、填写更新说明，默认勾选“强制更新”，点“上传并发布”。包名、版本号与 SHA-256 自动识别，不符合时页面提示原因。
3. App 下次启动即弹出更新；旧版本低于“最低可用版本”时必须更新后才能使用。

安装包会自动生成公开外链，也可在“文件管理”中查看与复制；撤销该外链会让 App 无法下载更新。

## 5. App 接口地址

App 的接口地址只在打包时由 orange-app 仓库的环境配置文件决定（`config/test.json` 指向本测试服务器），App 界面不提供、不展示服务器地址。服务器地址或端口变化时修改对应 JSON 后重新打包：

~~~powershell
flutter build apk --release --dart-define-from-file=config/test.json
~~~
