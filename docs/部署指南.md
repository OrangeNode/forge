# 部署指南

本文件记录测试服务器的 Docker 部署方式。2026-10-08 起，用户要求把后端与管理端部署到测试服务器，供 App 真机测试；此前“不做服务器部署、不制作应用镜像”的范围因此调整（见[需求与范围](需求与范围.md)）。正式环境的域名、证书与 HTTPS 尚未纳入。

## 1. 组成

部署文件在仓库 `deploy/` 目录，一个 Compose 项目包含四个服务：

| 服务 | 镜像 | 对外 | 说明 |
| --- | --- | --- | --- |
| mysql | `mysql:8.4.11` | 否 | 命名卷 `mysql-data` 持久化 |
| redis | `redis:8.10.1-alpine` | 否 | 口令认证、AOF 持久化，命名卷 `redis-data` |
| backend | `eclipse-temurin:21.0.8_9-jre-noble` + 本地构建的 jar | 否 | 不启用开发 profile（接口文档关闭）；上传文件在命名卷 `forge-files` |
| web | `nginx:1.28.0-alpine` + 管理端 `dist` | 是（`ADMIN_PORT`、`APP_PORT`、`HTTP_PORT`） | 托管管理端页面，按入口把接口反向代理到后端 |

2026-10-09 起 web 分入口（`deploy/web/nginx.conf`，具体 location 在 `snippets/admin-site.conf`、`snippets/app-site.conf`），对外端口与域名只写在服务器 `.env`：

| 入口 | 容器端口 | 提供 | 不提供 |
| --- | --- | --- | --- |
| 后台入口 `ADMIN_PORT` | 8081 | 管理端页面、`/api/admin/`、`/api/public/`（后台复制的公开外链） | App 接口，其他 `/api/` 一律 404 |
| App 入口 `APP_PORT` | 8082 | `/api/app/`、`/api/public/`（接口与安装包下载） | 后台页面与后台接口 |
| 域名入口 `HTTP_PORT`（80），Host 为 `ADMIN_HOST` | 80 | 与后台入口相同 | 同后台入口 |
| 域名入口 `HTTP_PORT`（80），Host 为 `API_HOST` | 80 | 与 App 入口相同 | 同 App 入口 |
| 80 端口其他 Host（直接用 IP、其他子域名） | 80 | 不返回内容，直接断开（444） | 全部 |

2026-10-12 起 80 端口按域名分流（只用 HTTP）：`nginx.conf` 是模板，web 容器启动时把 compose 传入的 `FORGE_ADMIN_HOST`、`FORGE_API_HOST`（来自 `.env` 的 `ADMIN_HOST`、`API_HOST`）替换进 `server_name`，只替换 `FORGE_` 开头的变量。高位端口入口保留给 1.0.7 及更早的 App，等新版本普及后再决定是否关闭；在 `.env` 设 `HTTP_BIND=127.0.0.1` 即对外关闭 80 端口。MySQL、Redis 与后端只在 Compose 内网中可达。

**Docker 发布的端口不受 ufw 控制**：容器端口由 Docker 直接写入 iptables，`ufw deny` 挡不住，关闭入口只能改 `compose.yaml` / `.env` 的端口绑定。

后端位于 nginx 之后，`FORGE_FORWARD_HEADERS_STRATEGY=native`（`application.yaml` 中 `server.forward-headers-strategy`）让 Tomcat 从内网代理传入的 `X-Forwarded-For` 还原客户端地址；nginx 覆盖写入该请求头，客户端无法伪造。限流与登录日志因此按真实来源计算。

## 2. 构建（本机，仓库根目录）

~~~powershell
# 后端 jar（测试已在本机 clean verify 通过时可跳过测试）
cd backend; .\mvnw.cmd -B package -DskipTests; cd ..
# 管理端 dist
cd frontend\admin; pnpm run build; cd ..\..
# 复制到 deploy/（两者均被 .gitignore 忽略）
Copy-Item backend\forge-application\target\forge-application-1.0.0.jar deploy\backend\app.jar -Force
Remove-Item -Recurse -Force deploy\web\dist -ErrorAction SilentlyContinue
Copy-Item -Recurse frontend\admin\dist deploy\web\dist
~~~

## 3. 上传与启动（服务器）

服务器需要 Docker Engine 与 Compose 插件。项目目录 `/opt/orange-forge`，上传 `deploy/` 下的全部内容（`compose.yaml`、`.env.example`、`backend/`、`web/`，含 `web/snippets/`）。

首次部署在服务器生成 `.env`（只在服务器保存，`chmod 600`）：

~~~bash
cd /opt/orange-forge
cp .env.example .env && chmod 600 .env
# ADMIN_PORT、APP_PORT 选未被占用的高位端口，并在 ufw 与云厂商安全组放行
# 每项口令用随机值，例如：
openssl rand -hex 24          # MYSQL_ROOT_PASSWORD、MYSQL_PASSWORD、REDIS_PASSWORD
openssl rand -base64 32       # FORGE_FILE_ENCRYPTION_KEY
openssl rand -base64 12       # FORGE_INIT_ADMIN_PASSWORD
# 服务器无法访问 Docker Hub 时：在本机 docker pull 后 docker save | gzip 上传，服务器 gunzip -c ... | docker load
docker compose up -d --build --wait
docker compose ps
docker compose logs -f backend
~~~

更新版本：重新执行第 2 节构建，只上传 `backend/app.jar` 或 `web/dist`，再 `docker compose up -d --build backend web`；改了 nginx 配置时连同 `compose.yaml`、`web/nginx.conf`、`web/Dockerfile` 与 `web/snippets/` 一起上传。数据卷不受影响；不要用 `docker compose down -v`。

注意：

- MySQL 初始化变量只在空数据卷时生效；之后修改 `.env` 中数据库口令需要在库内 `ALTER USER`。
- 初始管理员只在管理员账号表为空时创建，之后修改 `.env` 中的初始口令不会改变已有账号。
- 普通用户用用户名 + 密码注册登录（2026-10-08 起），不需要配置发信服务；服务器 `.env` 中旧的 `FORGE_MAIL_*` 行不再被读取，可以删除。
- 防火墙（ufw）只放行 SSH 端口与 `ADMIN_PORT`、`APP_PORT`、80；云厂商安全组需要在控制台另行放行。Docker 发布的端口不受 ufw 控制（见第 1 节）。

## 4. App 发布新版本

1. 在 orange-app 提高 `pubspec.yaml` 的版本号（`1.0.2+3` 中 `+` 后的数字必须比当前已发布的大），用正式签名打包（见 orange-app README）。
2. 后台“App 管理 → 版本更新”选择 APK、填写更新说明，默认勾选“强制更新”，点“上传并发布”。包名、版本号与 SHA-256 自动识别，不符合时页面提示原因。
3. App 下次启动即弹出更新；旧版本低于“最低可用版本”时必须更新后才能使用。

安装包会自动生成公开外链，也可在“文件管理”中查看与复制；撤销该外链会让 App 无法下载更新。

## 5. App 接口地址

App 的接口地址只在打包时由 orange-app 仓库的环境配置文件决定（`config/test.json` 指向本测试服务器），App 界面不提供、不展示服务器地址。2026-10-12 起 `config/test.json` 为 App 接口域名 `http://api.orangenode.cn`（1.0.8 起生效）；1.0.3—1.0.7 使用 App 高位端口 `http://103.242.13.62:39280`。服务器地址或端口变化时修改对应 JSON 后重新打包：

~~~powershell
flutter build apk --release --dart-define-from-file=config/test.json
~~~

## 6. 测试服务器访问地址与安全措施（2026-10-09）

| 用途 | 地址 |
| --- | --- |
| 后台 | `http://admin.orangenode.cn/`（2026-10-12 起；`http://103.242.13.62:47120/` 仍可用） |
| App 接口（1.0.8 起） | `http://api.orangenode.cn` |
| App 接口（1.0.3—1.0.7） | `http://103.242.13.62:39280` |
| App 接口（1.0.2 及更早） | 2026-10-09 用户确认后已关闭 80 端口（`LEGACY_HTTP_BIND=127.0.0.1`，ufw 规则已删除），这些版本已无法连接 |
| SSH | `ssh -i ~/.ssh/orange_deploy_ed25519 -p 42722 root@103.242.13.62`（只允许密钥登录） |

已落实的措施：

- 后台登录要填图形验证码（一次有效、两分钟过期）；同一账号连续输错 5 次锁定 15 分钟，同一来源地址 15 分钟内失败 20 次也会被拒绝。
- nginx 按来源地址限流：接口每秒 20 次，登录与注册每分钟 10 次，验证码每分钟 30 次，公开下载每个地址最多 4 个并发；超限按统一协议返回 `body.code=429`。
- 后台页面带 CSP、`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy` 等安全响应头；不暴露 nginx 版本；接口文档在部署环境关闭，入口也不转发 `/v3/api-docs`。
- 容器全部 `no-new-privileges`，后端以非 root 用户运行并去掉全部 Linux 能力；数据库、Redis、后端不发布端口。
- SSH 只允许密钥登录，`X11Forwarding no`、`MaxAuthTries 3`、`LoginGraceTime 30`（`/etc/ssh/sshd_config.d/10-orange-hardening.conf`）；fail2ban 对 SSH 10 分钟内失败 5 次的来源封禁 1 小时（`/etc/fail2ban/jail.d/orange-sshd.local`）。
- 凭据只在服务器 `/opt/orange-forge/.env`（600），2026-10-09 修改前的备份为同目录 `.env.bak-20261009`（600）。

尚未落实、需要用户决定的事项：

- **HTTPS**：目前全部是明文 HTTP，后台口令与令牌在网络上可被截获。2026-10-12 已有域名，用户决定暂不启用 HTTPS；以后启用可用 Let's Encrypt 免费证书（需放行 443）。
- **管理员口令强度**：口令最短 5 位是 2026-09-29 按用户要求放宽的，生产环境建议恢复到至少 12 位。
- **后台来源限制**：后台入口目前对所有地址开放，若管理员有固定出口地址，可只允许这些地址访问。
- 服务器上另有 ufw 放行的 8054 端口（不属于本项目，未改动）。
