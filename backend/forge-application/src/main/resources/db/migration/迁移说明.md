# 数据库迁移目录说明

本目录存放 Flyway 迁移脚本，随所属模块一起打入 classpath。

- M1 阶段没有业务表，因此没有迁移脚本；空文件或占位脚本会让 Flyway 校验失败，不建立空迁移。
- M3 起在 `system/` 子目录新增脚本：`V20260930120000__init_system_tables.sql` 创建管理员、角色、菜单、权限及三张关系表，并种入超级管理员角色与“概览”菜单。已在真实 MySQL 8.4 上执行成功，重复启动不重复执行。
- 各业务模块的脚本放在 `db/migration/<模块名>/` 子目录，避免不同模块的版本号互相冲突；
  Flyway 的 `locations` 为 `classpath:db/migration`，会递归扫描子目录。
- 版本号全局唯一，已发布的脚本不可修改，只能通过新增脚本演进结构。
- Flyway 只针对主库 `master` 运行，不自动初始化或迁移客户外接数据库。
- `spring.flyway.enabled=false` 会关闭迁移组件（M3 修复：初版装配时没有判断该开关，内存库测试因此会执行 MySQL 脚本并启动失败）。
- 校验方式：`mvnw.cmd -B install`，以及启动后用真实 MySQL 观察 `flyway_schema_history`。
- 内存库测试不执行本目录脚本（脚本使用 MySQL 专有语法），测试表结构由测试夹具单独维护，见 M3 任务第 4 节的说明。

配置位置：`spring.flyway.locations` 见 `forge-application/src/main/resources/application.yaml`；
针对主库的显式装配见 `forge-framework` 的 `FlywayConfig`。
